# UI 输入与默认值

本文记录模拟创建和运行期间由用户界面提供的输入规则。UI/UX 细节仍可迭代；这里仅固定输入归属和当前已讨论的默认场景。

## 输入责任

- 用户输入、用户命令、Slice 启用选择及其默认值由 Presentation/UI 收集或提供。用户可以接受默认值而不逐项填写。
- Application 接收 UI 提交的完整 context 和命令，负责用例流程、持久化和向单月计算传递明确参数。Application 不定义产品默认值，也不从 Core 推导用户设置。
- Core 只验证计算所需的不变量并执行计算。用户未启用的 Slice 不参加该月计算，不产生事件、状态变化、Ledger 分录或现金流影响；未启用 Slice 的专属参数不要求填写。
- 初始化提交后，本次模拟的配置固定。运行期间不提供配置编辑或 Slice 启停；用户可以停止模拟，或计算下一个月。要使用其他假设，需创建另一项模拟。

## 应用页面与导航

- 桌面应用使用一个持续存在的应用 shell，顶部保留应用名称、当前模拟名称和主要页面入口。初始化、月度运行、历史与趋势、模拟总结在同一窗口中切换；不为每个流程单独创建窗口。
- 页面路由由应用 shell 管理，页面内容由各自工作流页面负责。月度运行、历史与趋势和模拟总结是不同的页面职责；模拟总结聚焦全周期概览，逐月查阅由历史与趋势页面承担。
- 模拟总结展示截至最后已保存月份的财务位置、Month 1 起的期间损益，以及按经营/投资/融资类别和科目汇总的累计现金流；流入和流出分开呈现。仅有 Month 0 时展示期初财务位置，并明确没有已完成的模拟期间，不生成期间损益或现金流。
- 页面在小窗口和较窄布局下应允许纵向滚动，避免内容被窗口边界裁切。多栏内容可在窄布局中改为纵向排列或折叠区域。

## 初始化检查与开始首月

- 初始化前提供“检查并初始化”步骤，供用户核对期初事实、贷款条款、启用的模拟项目和停止条件，再明确提交初始化。
- 初始化之后、开始 `Month(1)` 之前，再提供一次开始提示，说明 `Month(0)` 是初始化边界、首个计算期间为 `Month(1)`，并概览本次模拟将使用的主要假设和停止条件。用户确认后配置在本次模拟中固定。

## 月度运行页面

- 月度运行页面以推进和检查一个月为中心，显示当前已完成月份、停止条件和“计算下一个月”操作；推进一次只计算一个月。模拟没有预设固定时长，停止条件满足后不再启动下一月。
- 页面提供月份选择或时间线，允许查看已完成月份。查看历史月份时，应清楚标示所选月份；推进操作仍指向下一个待计算月份，历史查看不触发重新计算。
- 选中月份展示该月摘要，以及事件、现金流分类和 Ledger 分录等可审计明细。摘要数值应由已保存的月度结果和 Ledger 投影得出。
- 负现金流、贷款未结清等可计算结果按结果展示，不应使用表示计算失败的界面状态。

## 历史与趋势页面

- 历史与趋势页面组合逐月现金流图表和月份列表，供用户浏览过往月份并理解现金流随模拟期间的变化。页面不替代月度运行操作。
- 图表以模拟月份序号（`Month(1)`、`Month(2)` 等）为横轴，不将序号呈现为日历月份或日期；`Month(0)` 初始化分录不作为模拟期间的月度现金流。
- 图表至少展示逐月净现金流，并提供经营、投资、融资分类的查看方式。图表明确显示零基线和正负方向；金额来自 Ledger 推导出的现金流。
- 选择图表中的月份时，同步选中月份列表中的对应项，并可进入该月的详细结果。月份列表在月数较多时可滚动。
- 首版优先保持图表和列表清晰可读，不要求多种图表类型。房产价值等没有逐月变化模型支持的量，不应绘制成模拟趋势。
- 窄屏布局将图表和月份列表纵向排列；单月明细可转为单独页面或折叠面板，避免强行维持多栏布局。

## 模拟期间的操作

- 初始化确认后，配置对本次模拟保持不变；不提供模拟期间修改配置。创建另一项模拟是独立流程，不会改动已有模拟。
- 月度运行页面的主要操作是计算下一个月和停止模拟。每次推进完整计算并保存一个月；用户不能在月度计算中插入配置编辑步骤。
- 用户停止和满足任一自动停止条件都会结束模拟，不会再启动额外月份。历史查看不改变配置，也不触发重新计算。
- Reset simulation 通过单独的系统操作确认后放弃当前内存中的运行并回到初始化；原模拟的已保存数据保留，但当前应用还不能重新打开它。

## 可直接运行的默认场景

用户不修改任何字段也可以开始模拟。UI 提供以下建议默认值，并允许用户调整：

| 输入 | 建议默认值 |
|---|---|
| 模拟起始位置 | `Month(0)` 是初始化边界；首个实际计算期间为 `Month(1)` |
| 默认货币 | CAD，可由用户调整 |
| 房产价格 | CAD 1,000,000 |
| 贷款期初余额 | 房价的 70% |
| 期初权益 | 资产、现金与负债平衡后的 CAD 300,000 |
| 固定年利率 | 5% |
| 剩余还款期限 | 240 个月 |
| 期初现金 | 0 |
| 房屋状态 | 可用 |
| 未配置的租金金额 | 0 |
| 贷款 Slice | 默认启用，以匹配默认的“贷款全部清零”停止条件 |
| 其他 Slice | 可由用户启用；未启用的 Slice 不影响模拟 |

房产价格、贷款余额、期初现金和权益是明确的用户起点事实；Application 根据这些事实和账户角色映射生成 Month 0 JournalEntry。该分录是模拟初始化记录，不代表模拟开始前发生的经济交易。示例为房产资产 1,000,000、现金 0、贷款负债 700,000、期初权益 300,000。

## 停止条件

首版只提供两类停止条件：

- 用户设定的模拟月数。
- 贷款全部清零。

默认启用“贷款全部清零”。用户可只选期限，也可同时选择两者；多个条件采用 OR 语义，任一满足即停止。若用户同时设置期限和贷款清零，以先满足者为准。模拟期间用户可选择结束模拟并进入报告阶段；该操作独立于自动停止条件。

“贷款全部清零”按所有已配置贷款的 Ledger 余额判断，不受用户是否启用对应 Slice 影响；停用未结清贷款不会把它视为已清偿。期限条件从模拟起始月计数且包含首个模拟月，因此期限为 1 表示完成首个月后，在下个月开始前停止。若所有贷款 Slice 均停用、贷款余额仍大于零且只选择清零条件，UI 应要求设置期限；用户也可随时选择结束模拟。

模拟也可在贷款结清前因期限或用户选择结束而停止。此时保留实际 Ledger 余额、最后月份结果和由已保存结果推导的报告；未结清贷款是正常的期末结果，不是计算错误，也不隐式结清。

## 暂不要求的用户资料

当前计算没有使用的房产地址、面积、购入日期、家庭成员或其他背景资料不作为必填输入。新增输入须对应明确的计算或呈现用途。

## 与 Application 的交互

UI 通过 Application 用例设置初始值、推进一个月、停止模拟、获取统计报告和读取指定月份完整结果。月度推进不接受配置变更；用户停止通过独立的停止操作提交。UI 回看某月时读取已经保存的完整结果，不要求重新运行该月计算。
