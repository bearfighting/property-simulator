# 桌面应用设计

> 本文保留原规范章节编号，便于和既有讨论对应。首版实施基线以本文及 [实施路线](implementation-roadmap.md) 为准。

> 本文保留早期 GPUI 产品构想，不是已确认的应用设计。当前尚未设计 CLI/GUI 工作流或多场景调度。界面经 Application 调用用例；Application 负责通过 Data Access 读取输入、调用 M6 单月整合并持久化结果。所有页面和交互均须在界面阶段重新评估。

## 14. GPUI Desktop 产品设计

### 14.1 核心页面

1. **Project/Scenario Library**：创建、复制、打开实验。
2. **Scenario Builder**：预设选择、事实与假设分区、活动实例与计算规则配置、校验、开始。
3. **Monthly Timeline**：按年折叠/按月展开，事件、结算、状态变化。
4. **Event Inspector**：来源、条件、风险、因果链、Effects、相关 Ledger。
5. **Decision Panel（未来能力）**：未来若加入交互式决策，可展示维修/融资等选项并控制暂停与继续；当前时间线只检查已生成的事件、策略决策和结果。
6. **Ledger Explorer**：月度明细、账户余额、交易来源；不展示投资建议。
7. **Export/Save**：数据集格式、范围、保存/恢复。

### 14.2 交互原则

- 月度为最小导航单位，默认按年汇总；
- 常规付款可折叠，重大事件突出；
- 每月显示 opening/closing balance、事件数和现金变化；
- 高级概率参数放在可展开的技术面板；
- 交互式决策、逐月停止、已保存结果编辑、分支和运行进度展示均未设计；本文件不设定这些行为。
- 当前 Core 与 M6 单月整合是同步计算模块，不管理场景集合。多场景和并行调度尚未纳入当前工作；若将来需要，由更高层设计（见 [ADR-26](adr/ADR-26-scenario-scoped-runtime-and-concurrency.md)）。

### 14.3 Scenario Builder 表单生成

预设是应用配置数据；表单可使用默认值、字段类型和必填提示等元数据辅助录入，并负责格式解析和交互提示。领域不变量及跨字段约束由 Rust 核心校验器统一负责，UI 展示其校验结果，不重复实现领域规则。首版允许部分表单手写，不要求完全自动生成动态表单。
