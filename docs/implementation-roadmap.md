# 实施路线与里程碑

> 本文保留原规范章节编号，便于和既有讨论对应。本文是当前里程碑与实施顺序的权威来源；领域定义见 [domain-model.md](domain-model.md)，工程门槛见 [engineering-practices.md](engineering-practices.md)。

> 早期里程碑 checklist 记录各阶段完成时的行为及回归测试，不自动代表当前生产 API。M3/M4 的运行控制、月度组合和归档实现经过 M5 前置整改后仅存在于测试支持目录。当前阶段边界为：M5 完成底层 Core 模块；M6 实现单月计算整合；应用层与数据访问层在后续阶段设计。后续 ADR 和本节的当前边界说明优先于历史 checklist。

## 20. 实施计划：领域内核优先

本节把已确认的架构原则转成可执行计划。若本节与第 15、19 节的旧里程碑排序冲突，以本节为准；业务边界以 [产品概览](overview.md) 和 [领域模型](domain-model.md) 的当前基线为准，已确定的设计方向见 [ADR 归档](adr/README.md)。第一阶段完成底层模块及单月计算整合；应用层负责连接界面、数据访问和计算模块，具体按后续阶段实施。

### 20.1 首阶段设计目标

首阶段分步完成可独立调用的 Rust 底层模块与单月整合函数：M5 完成模块自身，M6 连接这些模块形成单月输入/输出。它们能够：

1. 描述任意有效起始期的充分状态，包括用户事实和此前生成且仍影响计算的状态；每个同步计算调用只接收当前需要的数据，不由 Core 持有跨月运行状态或完整历史。
2. 底层模块各自以显式输入计算并返回结果；模块之间只依赖共享类型或窄接口，不直接调用其他模块的具体实现。
3. M6 的单月整合以“完整期初状态 + 当期冻结输入 + 当期随机输入 → 完整月度结果”为边界。结果包括事件、状态变化、Ledger 更新、从 Ledger 推导并按实例归属的现金流序列，以及期末状态。重复月份的调用、数据读写和停止条件由之后的应用层处理。
4. 组合至少两个 Slice；实例彼此独立计算，组合满足交换律和结合律；无法兼容组合的结果在生成完整月度结果前拒绝。
5. 以复式记账保存经济事实，并从总账推导资产负债表、利润表和现金流视图。
6. 为独立模块和单月结果提供可比较的测试 fixture；不在 Core 中保留整次模拟的数据集或历史。应用界面和文件导出不属于本阶段完成条件。

240 个月是一个长期回归场景，不是模拟固定长度或领域 API 的约束。所有区间均由起止年月指定，允许从任意有效月份开始或分段延续。

可扩展性是首阶段的首要设计约束：新增初始配置参数或 Slice，应通过增加领域类型/配置字段、校验和相应策略实现完成，避免重写运行器、Ledger 或上层应用。扩展性不等于预先实现通用 DSL/插件系统；抽象必须对应已知变化边界并可测试。


### 20.7 分阶段里程碑与验收

**M0 — 设计决策与可运行骨架**

M0 的目标是让团队可以安全开始 M1 领域实现；它建立工程约束、模块边界和决策记录，不在此阶段实现完整 Ledger、贷款模型、CLI 或 GUI。

**M0 checklist**

- [x] **确认早期范围基线（历史）**：当时讨论过月度模拟、用户指定时长、月末快照分支和 trial 等运行概念；后续边界复核已将常驻运行、分支及多场景管理移出当前 Core/M5/M6 范围。仍有效的领域边界包括个人/家庭房产、不模拟破产/资金不足处置/逾期/违约/止赎、负物业现金流可继续、不把生成记录视为真实行为或法定会计记录。
- [x] **确定最小工程骨架**：选择 Rust 2024 edition、stable toolchain 和 Cargo workspace；建立 domain、accounting、simulation、models 四个最小 crate，并在架构文档明确职责及依赖箭头。尚无职责的 Infrastructure、CLI 和 GUI crate 暂不创建。
- [x] **建立 ADR 工作方式**：`docs/adr/` 有模板、编号约定和 ADR-01 至 ADR-17；每份记录状态、背景、决策、备选方案、后果及测试向量或说明不适用。
- [x] **完成 Ledger 基线 ADR**：说明首版个人/家庭账户类别、借贷方向、期初净值核对、收入费用分类和同月权责/现金简化，并给出开账、月供、维修、租金、税费及通用应计利息投影边界向量（L-07 不代表 ADR-14 的抵押贷款行为）。
- [x] **完成贷款利息 ADR**：锁定固定年利率除以 12、按余额/期限/利率推导等额月供、生效月作为首个整月计息及月末还款月、月初余额计息、利息优先还款、末期结清调整、十进制中间精度和货币最小单位 half-up 舍入；明确必需输入、生效月份、非法输入和边界向量。
- [x] **完成随机与分支 ADR（历史设计记录）**：当时记录四个随机范畴及暂定独立假设、`trial_id` 和分支语义。当前保留显式采样接口及范畴假设；运行/分支语义已由 ADR-27/29 取代，未完成运行恢复不属于当前要求。
- [x] **完成配置与运行控制约定（历史设计记录）**：当时记录初始配置、运行控制和月度输入快照，包括停止条件与分支规则。该运行控制/分支流程不是当前要求；配置输入与领域校验仍按现行边界执行。
- [x] **确定质量工具链**：`scripts/check.sh` 统一执行 `cargo fmt --all --check`、workspace Clippy（`-D warnings`）、workspace 编译和测试；GitHub Actions push 与 pull request 均调用该入口。warning 视为失败，lint allow 仅在有明确理由时局部使用。
- [x] **建立分层测试布局**：工程规范确定 domain 单元测试、application fake/in-memory 测试和后续 infrastructure 集成测试；固定 seed 仅用于测试/诊断。Ledger 与 mortgage 手算向量见 [test-vectors.md](test-vectors.md)。
- [x] **验证空骨架**：运行统一脚本验证 workspace 格式、lint、编译和测试；crate 依赖方向及职责见架构文档。此项仅验证工程骨架，不代表其余 M0 工作完成。

**M0 交付物**：最小可编译 Rust 工程、分层/依赖说明、ADR 模板及关键 ADR、质量命令/CI 配置、Ledger 与 mortgage 测试向量清单。

**M0 完成条件**：checklist 中所有首阶段必做项完成；关键领域语义没有相互矛盾；Ledger 与贷款公式有可手算凭证/数值样例；新成员可按文档运行质量命令并知道新增代码应放在哪一层。M0 不要求完成真实领域计算。

**M1 — 原语与 Ledger**

按以下顺序完成；后续任务依赖前面的类型与不变量：

- [x] **M1.1 基础值与标识类型**：在 `domain` 实现 `YearMonth`、带币种代码的十进制定点 `Money`、舍入策略及强类型不透明 ID。ID 由调用方提供；Ledger 单币种约束由 M1.4 的 Ledger 承载。
- [x] **M1.2 科目表与分类**：在 `accounting` 定义账户类别、由类别决定的正常余额方向、`AccountCode` 分段/排序、账户唯一性与有效性校验，以及直接现金流分类。代码仅用于识别、分组和排序，不决定借贷行为。
- [x] **M1.3 期初余额和余额推导**：实现期初账户余额记录与资产、负债、权益核对；期初事实不创建模拟期间凭证或现金流。允许净资产为负，只要开账借贷平衡；账户余额由期初余额推导。
- [x] **M1.4 复式凭证过账**：实现交易与分录的结构校验、账户引用和币种校验、非负分录金额、借贷平衡校验、过账状态及余额重算。拒绝不平衡或重复交易 ID；不得将本金还款记作费用。
- [x] **M1.5 财务投影**：从期初余额和已过账分录推导账户余额、资产负债表、利润表及直接法现金流（经营/投资/融资）。不维护平行手写合计；非现金分录不进入直接法现金流。
- [x] **M1.6 向量与里程碑验收**：将 [Ledger 测试向量](test-vectors.md#ledger-vectors)落实为 domain/accounting 测试；覆盖开账、凭证平衡/拒绝、余额重算、负净资产、币种不匹配、现金流分类和报表对账，并运行 `./scripts/check.sh`。

**M1 完成条件**：M1.1–M1.6 全部完成；期初资产/负债不变成期间流水；现金、贷款、权益、损益与现金流投影可从账簿对账。M1 不实现贷款利息计算（属于 M3），也不实现月度运行器（属于 M3）。

**M1 按有效输入无运行时失败原则复核（M2 前跟进）**

M1 原验收证明了账务不变量和拒绝非法凭证；此项复核进一步区分输入边界校验与有效模拟结果，避免把模拟过程中的可计算结果当成运行错误。此复核不撤销 M1 已完成状态，但复核发现的领域规则缺口须在依赖它的 M2/M3 实现前解决，并同步更新 ADR、向量和测试。

- [x] **分类 M1 错误边界（历史复核，2026-10-19）**：复核曾发现现金分类、投影前置条件和金额累计溢出可能延迟到计算阶段。后续整改已在交易提交时验证现金分类、通过 `ValidatedProjection` 前置检查投影范围与现金账户，并将有限 `i128` 的超界行为明确为 checked numeric error；当前实现以 ADR-19 和下方完成项为准。
- [x] **确认验证错误边界（历史复核，2026-10-19）**：复核确认可修正结构问题应在场景/期初/月度冻结/提交前验证，内部不变量破坏或基础设施故障不能归类为用户输入问题。验证边界与有限数值范围的最终契约见 ADR-19；当前 M1 实现状态见下方整改项。
- [x] **实现负现金头寸及 L-08 连续性**：科目可显式标记为 cash-position；仅该类资产允许贷方余额。跨月测试验证余额、资产/权益、净收入和现金流对账，不生成隐含融资活动。
- [x] **确定金额表示范围（2026-10-19）**：采用 `i128` 十进制系数与显式 scale（最多 28 位），不要求无限精度。超出表示范围或 checked 运算溢出会明确报错；不截断或回绕。金额仍须在合理输入边界校验，极端不现实的计算溢出可显式失败。
- [x] **复核投影前置条件并前移验证**：账簿按科目表的 cash-position 标记固定现金账户集合；交易提交时检查现金科目必须带分类、非现金科目不得带分类。`validate_projection()` 返回借用账簿的 `ValidatedProjection`，在调用 `project()` 前检查区间和配置一致性；有效投影只执行计算。
- [x] **完成 M1 实现整改与验证**：负现金头寸、开放年份类型、有界 `i128` Money、交易分类校验和独立投影验证结果已实现。测试覆盖跨账户、跨月的大额资产、累计净收入和现金流投影，以及 L-08 连续性与输入验证前置。超出数值表示范围的 checked overflow 是明确错误，不要求任意精度。单期充分状态/历史独立性测试随 M2 转移接口实现，不属于 M1 Ledger 原语验收。

**本次复核结论与下游顺序（2026-10-19）**：M1 复核整改现已落实于值对象、Ledger、投影验证入口和相关测试。单期充分状态及历史独立性契约见 ADR-18，并由 M2 单期转移测试落实；运行期限和停止条件仍由更高层运行控制负责。M3 贷款 Slice 沿用相同金额表示与现金账户/分类验证。负物业现金流继续是正常输出，不触发模拟终止或偿付能力处置。

**M2 — 月度活动与 Slice 基础**

- [x] **设计决策**：确定单期显式输入边界、Slice 提案契约、实例独立计算及交换/结合合并代数、稳定来源 ID 与分布/采样/Slice 职责分离（ADR-18、ADR-20；2026-10-20 明确不支持 Slice 间依赖或阶段）。
- [x] **示例与手算向量**：采用确定性租金收入和概率维修；维修样本为 `NoRepair` 或支持范围 `[0, 上限]` 内的 `Repair { cost }`。向量覆盖不发生、费用上下界、超界拒绝、经营现金流、非现金状态变化及负现金（[test-vectors.md](test-vectors.md#m2-monthly-activity-vectors)）。
- [x] **1. 身份与数据类型**：增加活动实例/Effect 强类型 ID；为当前租金/维修模型定义期初状态（现金与房况）、冻结输入、活动实例、带来源的类型化样本、事件/Effect/凭证草案及单期结果。Slice 只给出稳定输出键和提案内容；识别边界使用调用方注入的 `OutputIdFactory`，由月份、实例、输出类型和稳定键生成 ID，不要求 trial/branch 身份。识别后的三类输出保留来源元数据，合并边界检查各类型 ID 唯一性。
- [x] **2. 输入冻结与约束验证**：`validate_input` 汇总期初现金与账簿余额/币种、冻结金额、账户角色/引用、入账精度和当前有界维修支持的问题；通过时返回不可变的 `ValidatedInput`，Slice 提案入口只接受该类型，并在调用 Slice 转移逻辑前校验维修样本是否落在冻结支持内。`validate_proposal_transactions` 在克隆账本上调用同一批量过账校验，汇总可定位的分录问题，并预检重复 ID 和月末资产边界且不修改原账本。当前维修费用模型具有显式有限上界；具体分布律留给第 3 项。测试覆盖聚合报告、现金对账和无副作用的分录预检，`./scripts/check.sh` 通过。
- [x] **3. 分布、采样器与 Slice 接口**：维修分布以精确有理数定义发生概率，发生后费用在零至最大可表示整最小货币单位间均匀抽取；上限尾数向下取整。采样器从调用方注入的随机源取数并产出关联样本类型，随机源错误显式传播；Slice 只接收显式类型化样本且不持有 RNG。随机流分配留到 M3。
- [x] **4. 资源与提案合并**：声明读写资源；所有实例读取相同期初状态且不存在实例依赖/阶段。所有被接受的结果组合满足结合律、交换律和单位元；现金保留独立复式凭证、状态相同写入幂等合并且异值拒绝；预先拒绝未声明写入；稳定排序输出。详见 ADR-20 M2.4（按系统组合约定澄清）。
- [x] **5. 单期协调及示例 Slice**：`coordinate_month` 接收冻结输入、对应的期初 Ledger、已评估 Slice 输出和运行身份；每个输出绑定期初状态、冻结输入、资源声明及实际使用的类型化样本，ValidatedInput 绑定验证时账簿快照。协调器识别输出、校验来源/资源/样本、合并提案，在提交前验证 Effect 目标并预检交易，在 Ledger 副本批量过账，再从期末账簿推导现金、应用 `property.condition` Effect、构造完整月度结果。失败不修改调用方账簿；租金/维修组合与现金推导有集成测试。
- [x] **6. 失败出口与验收（M2.6，2026-10-19）**：增加带阶段、月份、可用运行/活动身份及原始类型错误的 fatal 诊断；Slice 转移、通过预检后的账簿提交、期末状态推导和结果构造错误不转换为经济结果。样本/资源/兼容性冲突/提案冲突/未知 Effect 和账簿交易预检失败继续属于可定位验证错误，交易报告保留交易键。协调器失败不返回成功结果且不修改调用方 Ledger；运行级 fatal 处理由后续运行控制定义，当前基线见 ADR-27：fatal 停止模拟，不设计失败运行恢复。有效组合与错误分类测试通过，`./scripts/check.sh` 通过。

M2 范围明确为通用最小 Slice 框架；不实现贷款、随机流分配、完整运行生命周期或通用 DSL/插件框架。每项实现仅在其代码和测试验收后勾选。

**M3 — 月度运行、随机流与首个领域 Slice**

**历史阶段记录：** 本节保留旧 M3 的运行控制、归档、分支及月度组合验收记录。涉及 `SimulationRun`、`coordinate_month`、快照历史、运行停止或分支的条目描述的是当时实现/测试，均不构成当前 Core/M5/M6 要求；M5/M6 的现行边界见下文及 ADR-27/29。可复用的领域规则与采样测试仍按各 ADR 保留。

- **M3.0 — 运行接口契约**
  - [x] 在 [ADR-16](adr/ADR-16-configuration-and-run-control.md#m3-run-call-contract) 定义后端单次调用行为：每次至多推进一个月，输入本次配置更新及 `Continue`/`Stop`，输出月度结果（若有）、最新运行状态及停止原因（若已停止）。具体 Rust 类型布局留给实现。
  - [x] 明确命令时序和责任：`Stop` 不调用单期转移；`Continue` 先校验/应用本期更新并冻结输入，再调用既有 `coordinate_month`；成功后生成结果和月末快照，再评估结束月份及条件，条件采用 OR 语义。
  - [x] 明确无预设结束月份/条件时，成功月份后运行保持可继续，由调用方逐月决定；更新验证错误发生于转移前，单期 fatal 作为模拟失败返回，不伪装成正常停止，也不生成该月成功结果或快照。
  - [x] 确认运行控制属于 `simulation` 编排职责，复用 M2 类型和协调器，不复制领域规则；不确定具体 Rust 类型布局、SQLite、UI、随机流实现或未完成运行恢复。
  - [x] 文档验收：契约覆盖单次最多推进一个月、停止不多推进、月末后评估，以及无配置停止条件时逐月由调用方控制。

- **M3.1 — 运行控制和月度输入**
  - [x] 按 [ADR-16 的 M3 调用契约](adr/ADR-16-configuration-and-run-control.md#m3-run-call-contract) 实现包含起始月份、可选结束月份及零个或多个月末终止条件的运行配置；一次调用至多推进一个月，且没有结束月份/条件时允许调用方逐期决定继续或停止。

  - [x] 严格按契约顺序执行：接收命令 → 校验/应用本期更新 → 冻结输入 →（Continue 时）运行单期转移 → 成功后生成结果和快照 → 评估月末条件/结束月份 → 返回结果、最新状态及停止原因（若已停止）。输入错误在转移前返回；fatal 是模拟失败，不是正常停止，且不产生该月成功结果/快照。

**M6 — 单月计算整合**

M6 在底层模块之上提供无持久化职责的单月计算入口。它以期初状态、当月有效输入和所需随机输入为参数，调用初始化/期初准备、独立 Slice 计算、月末结算及跨模块审计，返回一个包含 Ledger 变更和期末状态的完整月度结果。该入口只完成一次月度计算，不持有跨月运行状态。

- [ ] **M6.1 — 单月输入/输出契约**：定义充分期初状态、当期冻结输入/显式样本，以及月度结果；明确事件、Effects、Ledger 变化、来源、现金流投影和期末状态之间的一致性。
- [ ] **M6.2 — 期初准备与模块调用**：按接口调用相关底层模块，形成当月可计算输入；依赖注入或显式参数传递协作者，禁止中间层直接依赖具体 Slice 实现。
- [ ] **M6.3 — 单月 Slice 整合**：对相同期初状态和冻结输入下的独立 Slice 结果进行验证与组合；不建立 Slice 间依赖、阶段或顺序语义。
- [ ] **M6.4 — 月末结算与审计**：验证 Effects、事件来源、Ledger 交易、期末余额和现金流投影一致；通过 Ledger 规则原子地产生成功结果。失败调用不产生成功月度结果。
- [ ] **M6.5 — 单月失败边界**：可修正输入在进入计算前拒绝；模块计算错误向调用方返回类型化错误。失败时不返回部分成功结果；不设计运行恢复、重试、checkpoint 或随机状态重放。
- [ ] **M6.6 — 单月组合验收**：覆盖两个以上 Slice、Ledger 对账、来源追踪、现金流由 Ledger 推导、期初/期末状态一致、组合冲突拒绝及失败无成功结果。只在真实模块组合边界做集成测试。
- [ ] **M6.7 — 依赖与质量门槛**：确认 M6 仍是同步、无 IO 的计算整合模块，不引入 CLI/GUI、应用调度、数据访问、SQLite、分支或并行场景管理；同步文档与向量并运行质量门槛。

**M6 完成条件：** 一个明确的单月调用接收完整参数并返回一致的月度结果；中间层负责单月模块整合，底层模块仍保持独立；没有数据库访问、跨月运行器或应用层职责。

**后续阶段 — 应用层与数据访问层**

应用层位于最高层，负责一次模拟的调用流程，并且是 UI、数据访问和 M6 单月整合之间的唯一协调者。应用层通过数据访问读取用户输入、期初状态和 Ledger，将这些值作为参数传给单月整合模块，接收完整月度结果，再调用数据访问保存用户输入、月度结果/快照数据和 Ledger 记录。月度结果包含期末状态及 Ledger 派生的按实例现金流序列；结果中的 Ledger 更新与 Ledger 记录是同一批经济事实，不形成第二套账簿；现金流不作为竞争性的手工账务事实保存。数据访问只由应用层调用；UI 只调用应用层。数据库如何组织月度结果与 Ledger 记录留待该阶段设计。

SQLite 及其内部存储结构在该阶段具体设计。项目不承诺 schema 版本化、迁移或跨应用升级兼容；应用版本是唯一需要记录的软件版本。一次模拟失败即停止，不设计未完成运行恢复或重复计算流程。该阶段再细化单次模拟的应用用例和存储事务边界，不提前加入分支、并行调度或多场景管理。

**界面阶段 — CLI / GPUI**

CLI 或 GPUI 负责限制和解析用户可输入的格式、展示结果，并通过应用层启动用例；界面不直接访问数据存储，也不直接组装底层计算模块。界面具体工作流仍按实际需求设计。

**界面交付后的代码质量打磨**

在界面功能基本稳定后安排一轮以可读性和可维护性为目标的系统整理。此项工作不阻塞此前功能交付，也不预先扩大领域范围；若整理过程中发现需要改变领域规则或公开契约，先按现有 ADR 流程单独评估。

- 按模块审查职责、依赖方向、关键流程复杂度及重复实现；优先处理职责混杂、重复校验/转换和难以理解的长流程。
- 只有语义和不变量相同的实现才提取共享逻辑；删除代码前确认无调用方、无序列化/测试契约依赖，避免为了减少行数引入通用框架或过度细分模块。
- 以小批次进行行为保持型重构，保留并运行现有领域向量、单元/集成测试和统一质量门槛；领域行为变更须同步更新 ADR、领域文档和测试向量。
- 验收：模块职责与依赖边界清楚，关键编排流程可按命名阶段理解，重复代码的合并/保留均有语义依据，`./scripts/check.sh` 通过，且没有未说明的行为或数据契约变化。


### 20.8 测试策略

- 数学单元测试：贷款公式、概率/危险率、舍入、报表映射和借贷平衡。
- 单月边界测试：覆盖任意有效年月、月末结算和贷款结清状态。若后续 Application 需要停止条件或运行状态机，再由该层定义并测试。
- 连续性测试：将一次单月计算的期末状态和 Ledger 显式传给下一次调用，验证计算连续性；不在内存 Core 中建立快照历史或分支，也不测试未完成运行的 RNG checkpoint 恢复。
- 组合测试：Slice 结果的排列/分组不变性、兼容与冲突行为、实例间结果隔离、Ledger 批次校验及失败时不产生部分成功结果。
- 属性/不变量测试：借贷平衡、现金对账、贷款非负、期间连续、ID 唯一、来源引用有效。
- 固定 seed golden fixture 用于计算回归；当应用整体升级改变输出时，测试期望可随规则变化更新，不要求跨应用版本保持同一随机轨迹。统计性质测试使用固定 seed 集合与有容差的显著性界限，避免脆弱的单次随机断言。
- 测试覆盖不同持续时间，但不存在“模拟必须运行 240 个月”的业务断言。


### 20.9 已确定基线与后续技术决策

以下原则已由项目方向确定，不再作为启动编码的开放问题：

1. 月利率首版按名义年利率除以 12；用户提供期初余额、剩余期限和固定年利率，月供按等额摊还公式推导，按月初余额计息，月末先付利息再还本金；月供和利息按币种最小单位 half-up 舍入，最后一期调整至结清。不模拟自定义月供、漏付、逾期或违约。精确定义见 [ADR-14](adr/ADR-14-mortgage-interest.md)。
2. 首版账簿以个人/家庭持有一套房产为模拟主体，期初只覆盖明确纳入账簿范围的事实；现金流从 Ledger 现金分录及来源推导，按活动实例形成序列，Slice 实现与活动实例不要求一一对应。M3 贷款使用逐实例负债科目并按实例对账，利息费用科目共享，见 ADR-23；不模拟资产折旧/摊销。负物业净现金流是计算结果，不代表家庭偿付能力，也不产生隐式停止信号。
3. 随机模型按自然环境、房屋/组件、政策/宏观、居住/运营四类组织；首版范畴间独立处理。仅在具体模型证明有必要时再设计相关性。
4. 月末状态可作为单月结果的一部分返回。应用层以后按月份顺序调用，并保存用户输入、完整月度结果/快照数据和 Ledger 记录；月度结果包含期末状态与 Ledger 派生的现金流序列。当前不设计历史分支。一次模拟顺序推进，每个已完成月份不在该流程中重复计算。
5. 首版不保证应用升级后的数据向后兼容。fatal 错误停止本次计算，不恢复或重试失败运行。月度结果与 Ledger 的保存职责归后续 Application/Data Access 阶段；数据库内部组织留待该阶段决定。随机种子和发生器状态不作为失败恢复信息持久化。详见 [ADR-21](adr/ADR-21-m3-run-randomness-and-persistence.md)、[ADR-26](adr/ADR-26-scenario-scoped-runtime-and-concurrency.md) 和 [ADR-27](adr/ADR-27-current-month-runtime-and-database-owned-history.md)。

已接受的细节见 [ADR 归档](adr/README.md) 与 [测试向量](test-vectors.md)。遇到真实模型需求时通过新 ADR 记录设计演进，不为假想需求提前构建通用规则语言或相关性插件框架。
