# 项目概览与产品范围

> 本文保留原规范章节编号，便于和既有讨论对应。首版实施基线以本文及 [实施路线](implementation-roadmap.md) 为准。

> **当前实现状态：** 下文描述产品目标。当前生产代码尚未形成完整月度运行系统；M5 前置整改完成后，M5 将定义纯输入/输出的月度计算边界。现有完整运行、快照和分支组合只作为测试支持保留。

> 核心原则：**输入状态定义计算起点；Slice 定义领域计算；事件与 Effects 解释变化；Ledger 记录经济事实；结果由调用方接收。**

## 1. 愿景、边界与验收目标

### 1.1 目标

创建一个可配置、可审计的房产生命周期模拟器。当前产品范围面向个人/家庭持有的一套房产；房产可有零笔、一笔或多笔独立贷款。目标是由调用方提供初始状态和当期输入，Core 逐月执行纯计算并返回完整月度结果和期末状态。历史保存、数据库及分支流程暂不属于当前 Core 范围。

**不预测某套真实房屋的必然未来**。默认概率参数是可解释的演示/估计假设，只有经过来源标注和校准的参数才能声称具备相应实证依据。

### 1.2 当前范围与明确不做

- 单次 Core 调用计算一个月。是否再次调用、调用多少次以及如何停止，由以后设计的更高层流程决定；当前 Core 不定义运行控制。
- 负的房产范围净现金流是有效计算结果，不代表偿付能力问题。当前范围不模拟家庭整体偿付能力、资金不足处置、破产、逾期、违约或止赎。
- 事件与流水是模型生成的模拟记录，不代表真实行为记录，也不是法定、税务用途的会计记录或正式报告。
- 持久化结果的组织和重新计算流程留待应用/存储阶段讨论；当前不决定是否支持分支。
- 交互式暂停等待用户决策、按资金不足改变支付行为，以及基于“像不像现实”阻止输入，均不属于当前范围；这些是未来可能显式设计的能力。

- 投资建议、回报率评分、IRR/NPV、投资组合优化；
- 法定/税务用途的正式财务报表、完整会计准则或会计合规实现；
- 宏观经济均衡模型、精准天气预测、建筑工程级仿真；
- 云端账户、多人协作、动态插件市场；
- 一开始就建立通用规则 DSL、通用会计 ERP 或分布式事件平台。

**允许**基础的数据完整性摘要（每月收支、余额、未偿本金、组件状态、事件计数）；它们是数据投影，不是财务分析报告。

### 1.3 第一版成功标准

Core 接收期初状态、当期有效输入及所需随机输入，逐月返回完整结果和期末状态。结果包含事件、状态变化、Ledger 更新，以及从 Ledger 现金分录和来源推导的现金流序列。用户可将上一月期末结果作为下一月的输入。SQLite、历史查询和分支行为留待后续阶段再决定；当前 Core 不保存完整历史。详见 [ADR-27](adr/ADR-27-current-month-runtime-and-database-owned-history.md)。


## 3. 核心概念与术语

| 概念 | 含义 | 示例 |
|---|---|---|
| Calculation input | 一次月度计算的期初状态、当期输入和所需显式随机输入 | 已持有房产，2030-01 的输入 |
| Preset | 可覆盖的起点模板 | 已出租、无贷款 |
| Initial World State | 月初已存在的事实快照 | 贷款本金 275,000，屋顶 12 年 |
| Assumptions | 未来演化的模型与参数 | 利率重置策略、维修概率 |
| Activity Instance | 用户配置并在一个或多个指定月份生效的模拟活动 | 一笔独立贷款、定期保险费、一项维修规则 |
| Slice | 计算活动结果的领域代码/规则边界，与活动实例不要求一一对应 | 同一 mortgage 实现处理多笔贷款 |
| Process | 连续/周期性的状态演化 | 屋顶老化、贷款计息 |
| Event | 已发生的离散事实 | 维修需求、贷款结清 |
| Decision | 外部选择及其记录 | 修补/更换/延期 |
| Effect | 经过验证、将要应用的状态或经济变化 | 本金减少、屋顶状况改善 |
| Ledger Transaction | 同一业务动作的经济记录集合 | 月供的现金、本金、利息分解 |
| YearMonth | 单次月度计算的期间 | 2032-06 |
| Persisted result | 由后续应用/存储设计决定的月度结果记录，不是当前 Core 的常驻对象 | 2032-06 计算结果 |
| Monthly Result | 单月计算的完整输出 | 事件、状态变化、Ledger、现金流序列、期末状态 |

领域对象（房产、贷款、租约和组件）的状态变化属于单次计算；多月调用流程与运行终止规则尚未设计。


## 4. 未来输入界面概念（尚未设计）

以下预设和交互流程是早期产品构想，不定义当前 Core API、输入格式或运行控制。CLI/GUI 的输入工作流留待应用阶段设计。

### 4.1 用户流程

1. **选择预设**：首次购房、已持有且有贷款、无贷自住、已出租。
2. **提供计算期间**：每次月度计算需要一个有效 `YearMonth`；更高层如何组织连续月份尚未设计。
3. **编辑初始事实**：房产、现金、贷款、组件、租约等；只显示已启用 Slice 所需字段。
4. **编辑未来假设**：利率、通胀、天气、维修模型等用户可配置参数。随机源和采样器由调用方提供；固定 seed 可用于测试/诊断。
5. **预览和校验**：CLI/GUI 负责输入格式约束；Core 对类型化值检查计算所需的领域不变量。现实性/校准信息不作为计算有效性的判断。
6. **准备计算输入**：调用方提供期初状态、本月有效设置、活动实例和显式随机样本。Core 不管理已关闭月份、快照或分支。

### 4.2 两类独立预设

- **Scenario Preset**：起始世界状态；例如 `existing-mortgaged-home`。
- **Model Preset**：未来演化规则；例如 `baseline-maintenance`、`high-cost-environment`。

二者可以交叉组合。默认值分层：系统默认 → 地区配置（可选）→ 场景预设 → 用户覆盖。调用方为单次计算形成完整的有效输入。已保存结果的编辑和重新计算流程留待后续应用设计。

### 4.3 初始事实与假设分开

**事实：** 模拟起始时的现金、资产估值、贷款未偿本金、贷款条款、组件年龄/状况、租赁状态。
**假设：** 未来故障风险、成本分布、通胀、租客搬离概率、未来利率变化、维修策略。

初始房产估值是起点的估值数据，不是本月购房收入。期初现金不是本月资金流入；期初贷款也不是本月新增借款。

### 4.4 预设示例（示意参数，非市场事实）

```yaml
id: existing-mortgaged-home
scenario:
  start_month: 2030-01
  end_month: 2049-12
initial_state:
  property:
    ownership_status: owned
    estimated_value: { amount: '600000.00', currency: CAD }
  cash_accounts:
    - { id: operating, opening_balance: '25000.00', currency: CAD }
  loans:
    - id: mortgage-1
      outstanding_principal: '275000.00'
      annual_rate: '0.045'
      remaining_amortization_months: 240
  components:
    - { id: roof-1, kind: roof, age_months: 144, condition: 0.75 }
enabled_slices:
  - mortgage
  - property-tax
  - maintenance
assumptions:
  maintenance_policy: manual_above_threshold
```

此为帮助说明预设内容的示意 YAML，不是 M5 序列化格式承诺。CLI/GUI 负责解析各自输入；解析后的类型化配置仍由核心领域边界校验必要字段、引用、账务关系和跨字段计算约束。

按 ADR-14 的固定利率等额摊还约定，上述余额、年利率和 240 个月剩余摊还期推导出约 CAD 1,739.79 的月供；贷款计算输入只有余额、期限和年利率，月供是计算结果。示例中的贷款在 2030-01 计算时生效，当月计息并在月末首次还款；未来应用如何表示连续期间或变更安排尚未设计。本例不模拟合同续约或浮动利率。

### 4.5 校验规则

- 每次计算必须提供有效 `YearMonth`。Core 不要求固定模拟期限，也不定义结束月份或停止条件。
- 启用 M3 固定利率等额摊还 Mortgage 且未偿余额 > 0 时，必须具备正数期初余额、正整数剩余摊还月数和非负固定名义年利率；有效月份由活动时序提供。系统按 ADR-14 推导月供，不接受另行输入的月供金额。
- 已有租客时必须提供租金和支付周期，或明确选择默认规则。
- 组件状况必须在合法区间；安装年龄与状态可以相关，但不强制仅由年龄决定。
- 购房交易不得与已经入账的期初房产资产、贷款和现金重复计入。
- 初始余额不得被记录成当月 Ledger Transaction。
- 货币一致性；跨币种暂不支持或显式禁用。
- 启用 Slice 声明其所需实体和配置字段；缺失即报错。


## 18. 推荐的第一份可执行样例

**Scenario A — New Purchase**
- 2030-01 至 2049-12；2030-01 购入房产；首付+贷款；月供由贷款余额、固定利率和摊还期限推导；无租客；从第二个 Slice 开始加入税费。

**Scenario B — Existing Mortgaged Home**
- 2035-01 至 2054-12；已经持有房产；存在未偿贷款；不产生历史购房交易；贷款可能在模拟中途结清，模拟继续。

**Scenario C — Mortgage-free Rental**
- 2030-01 至 2049-12；无贷款，已有租客；租金、税费、维护叠加；后续可加入租客搬离与屋顶维修。

领域单元测试和固定 fixture 可使用固定 seed。未来应用如何组织重复计算或记录试验身份，留待应用设计；golden 输出属于当前应用版本的回归样本，不构成重放承诺。


## 附录 A：项目一句话定义

**Property Simulation Sandbox 的 Core 是以月度为单位的房产计算库：从有效期初状态和当期输入出发，由 Slice 计算并返回带来源的事件、状态变化、Ledger 更新、Ledger 派生现金流和期末状态。**


## 附录 B：最重要的边界

- Core 不管理 Simulation Lifecycle；调用方决定是否再次计算。
- Initial State 是**起始事实**，不等于过去事件历史。
- Slice 是**计算规则的代码边界**，活动实例是用户配置的模拟对象；两者不要求一一对应。Slice 不是独立提交的账本。
- Event 是**事实**，Effect 是**变化**，Ledger 是**经济记录**。
- 月度结果是**计算输出**；如何保存或展示留待应用层设计。
- GPUI 是**实验操作界面**，不是投资分析 Dashboard。
