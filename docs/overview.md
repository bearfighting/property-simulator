# 项目概览与产品范围

> 本文保留原规范章节编号，便于和既有讨论对应。首版实施基线以本文及 [实施路线](implementation-roadmap.md) 为准。

> 核心原则：**时间定义模拟边界；初始状态定义起点；Slice 定义领域演化；事件与 Effects 解释变化；Ledger 记录经济事实；数据集是产品。**

## 1. 愿景、边界与验收目标

### 1.1 目标

创建一个可配置、可审计、可分支重模拟的房产生命周期实验沙盒。v1 面向个人/家庭持有的一套房产；房产可有零笔、一笔或多笔独立贷款。用户选择预设、调整初始状态和未来规则，指定起止月份并运行场景。引擎逐月生成房屋状态、业务事件、决策、复式账簿经济流水与月末快照，最终形成可供其他软件消费的数据集。

**不预测某套真实房屋的必然未来**。默认概率参数是可解释的演示/估计假设，只有经过来源标注和校准的参数才能声称具备相应实证依据。

### 1.2 v1 边界与明确不做

- 模拟按月执行，只在到达用户预先设置的运行边界/终止条件，或用户发出月度停止命令时结束；贷款还清、净现金流变化、出售等不会自行结束模拟。没有固定模拟期限。20 年仅是可修改的界面默认值/示例长度。
- 负的房产范围净现金流是有效模拟结果，不代表偿付能力问题，也不会自动暂停或终止模拟；用户可显式将现金流阈值设为终止条件。v1 不模拟家庭整体偿付能力、资金不足处置、破产、逾期、违约或止赎。
- 事件与流水是模型生成的模拟记录，不代表真实行为记录，也不是法定、税务用途的会计记录或正式报告。
- 从月末快照创建分支会保留父分支，并启动新的随机试验；即使规则和参数不变，结果也可以不同。
- 交互式暂停等待用户决策、按资金不足改变支付行为，以及基于“像不像现实”阻止输入，均不属于 v1；这些是未来可能显式设计的能力。

- 投资建议、回报率评分、IRR/NPV、投资组合优化；
- 法定/税务用途的正式财务报表、完整会计准则或会计合规实现；
- 宏观经济均衡模型、精准天气预测、建筑工程级仿真；
- 云端账户、多人协作、动态插件市场；
- 一开始就建立通用规则 DSL、通用会计 ERP 或分布式事件平台。

**允许**基础的数据完整性摘要（每月收支、余额、未偿本金、组件状态、事件计数）；它们是数据投影，不是财务分析报告。

### 1.3 第一版成功标准

用户可以从任意有效初始状态或已完成月份快照开始，设置运行边界/终止条件或逐月发出继续/停止指令；贷款可在模拟前已存在、模拟中建立、模拟中结清或根本不存在。多个 Slice 叠加生成完整月度数据。每个月生成前，外部调用方可提供当月输入更新。规则和输入保持可审计；保存已完成快照/结果及最新用户设置。从已完成快照继续会开始新运行，不恢复未完成月份的随机状态。结构化结果可以导出。


## 3. 核心概念与术语

| 概念 | 含义 | 示例 |
|---|---|---|
| Scenario | 完整模拟输入：时间、初始事实、启用 Slice、规则、种子 | 已持有房产，2030–2050 |
| Preset | 可覆盖的起点模板 | 已出租、无贷款 |
| Initial World State | 月初已存在的事实快照 | 贷款本金 275,000，屋顶 12 年 |
| Assumptions | 未来演化的模型与参数 | 利率重置策略、维修概率 |
| Activity Instance | 用户配置并在一个或多个指定月份生效的模拟活动 | 一笔独立贷款、定期保险费、一项维修规则 |
| Slice | 计算活动结果的领域代码/规则边界，与活动实例不要求一一对应 | 同一 mortgage 实现处理多笔贷款 |
| Process | 连续/周期性的状态演化 | 屋顶老化、贷款计息 |
| Event | 已发生的离散事实 | 维修需求、贷款结清 |
| Decision | 外部选择及其记录 | 修补/更换/延期 |
| Effect | 经过验证、将要应用的状态或经济变化 | 本金减少、屋顶状况改善 |
| Ledger Transaction | 同一业务动作的经济记录集合 | 月供的现金、本金、利息分解 |
| Monthly Period | 月度执行与结算容器 | 2032-06 |
| Snapshot | 期初或期末世界状态 | 2032-06 closing state |
| Dataset | 可交换的模拟结果 | 事件、流水、状态、配置、元数据 |

**生命周期区分：** Simulation Lifecycle 由用户配置的结束月份、月度终止条件或逐月人工控制决定；Property Lifecycle、Mortgage Lifecycle、Lease Lifecycle、Component Lifecycle 是彼此独立的领域过程。出售房产可以停止其运营 Slice，但模拟继续至所配置的终止条件满足、结束月份到达或用户停止。


## 4. Scenario Builder：像 CRPG 捏脸一样创建世界

### 4.1 用户流程

1. **选择预设**：首次购房、已持有且有贷款、无贷自住、已出租。
2. **设置运行边界**：起始年月，以及结束年月、月度终止条件或逐月继续/停止控制中的至少一种。20 年可作为有结束月份时的可修改默认值。
3. **编辑初始事实**：房产、现金、贷款、组件、租约等；只显示已启用 Slice 所需字段。
4. **编辑未来假设**：利率、通胀、天气、维修模型、决策策略等用户可配置参数。系统生成运行时随机值；固定 seed 用于测试/诊断。
5. **预览和校验**：结构缺失、非法编码或无法计算的输入阻止运行；现实性/校准信息只能作为非阻断提示。系统按选定规则生成结果，不以“是否像现实”作为有效性判断。
6. **冻结 Scenario**：保存有效输入、版本和配置哈希；开始运行。之后每月先接收当月输入，可调整从该月起生效的状态/假设或新增、调整活动实例，再冻结该月输入。改变由 Ledger 表示的本月经济余额时，必须同时提供对应的状态 Effect 与平衡凭证；修改已关闭月份则从快照建立新分支。

### 4.2 两类独立预设

- **Scenario Preset**：起始世界状态；例如 `existing-mortgaged-home`。
- **Model Preset**：未来演化规则；例如 `baseline-maintenance`、`high-cost-environment`。

二者可以交叉组合。默认值分层：系统默认 → 地区配置（可选）→ 场景预设 → 用户覆盖。每月运行前形成完整的生效输入快照；快照在该分支的历史中不可静默修改，用户可从旧月末快照创建新分支并更新之后的配置。

### 4.3 初始事实与假设分开

**事实：** 模拟起始时的现金、资产估值、贷款未偿本金、贷款条款、组件年龄/状况、租赁状态。
**假设：** 未来故障风险、成本分布、通胀、租客搬离概率、未来利率变化、维修策略。

初始房产估值是起点的估值数据，不是本月购房收入。期初现金不是本月资金流入；期初贷款也不是本月新增借款。

### 4.4 预设示例（示意参数，非市场事实）

```yaml
schema_version: 1
id: existing-mortgaged-home
scenario:
  start_month: 2030-01
  end_month: 2049-12
initial_state:
  property:
    ownership_status: owned
    estimated_value: { amount: '600000.00', currency: CAD }
  cash_accounts:
    - { id: operating, opening_balance: '25000.00', currency: CAD }
  loans:
    - id: mortgage-1
      outstanding_principal: '275000.00'
      annual_rate: '0.045'
      payment_amount: '1739.00'
      remaining_amortization_months: 240
      next_payment_month: 2030-01
      rate_type: fixed
      term_end_month: 2034-12
  components:
    - { id: roof-1, kind: roof, age_months: 144, condition: 0.75 }
enabled_slices:
  - mortgage
  - property-tax
  - maintenance
assumptions:
  maintenance_policy: manual_above_threshold
```

上述贷款数值仅演示结构，**并未保证还款额与其他字段精确匹配**；有效运行必须执行条款一致性校验，并明确计息/还款约定。

### 4.5 校验规则

- 必须提供有效 `start_month`，并至少选择一种用户控制的结束方式：结束月份、至少一个月末终止条件，或逐月人工继续/停止控制；若提供 `end_month`，则须满足 `start_month <= end_month`。不设置产品层固定期限。
- 启用 Mortgage 且本金 > 0 时，必须具备利率、付款计划、计息约定、下一次还款时间、必要的续约假设。
- 已有租客时必须提供租金和支付周期，或明确选择默认规则。
- 组件状况必须在合法区间；安装年龄与状态可以相关，但不强制仅由年龄决定。
- 购房交易不得与已经入账的期初房产资产、贷款和现金重复计入。
- 初始余额不得被记录成当月 Ledger Transaction。
- 货币一致性；跨币种暂不支持或显式禁用。
- 启用 Slice 声明其所需实体和配置字段；缺失即报错。


## 18. 推荐的第一份可执行样例

**Scenario A — New Purchase**
- 2030-01 至 2049-12；2030-01 购入房产；首付+贷款；固定月供；无租客；从第二个 Slice 开始加入税费。

**Scenario B — Existing Mortgaged Home**
- 2035-01 至 2054-12；已经持有房产；存在未偿贷款；不产生历史购房交易；贷款可能在模拟中途结清，模拟继续。

**Scenario C — Mortgage-free Rental**
- 2030-01 至 2049-12；无贷款，已有租客；租金、税费、维护叠加；后续可加入租客搬离与屋顶维修。

领域单元测试和固定 fixture 可使用固定 seed；实际模拟分支生成独立试验 ID。golden 输出绑定模型/规则版本，作为软件回归样本，不代表用户重新模拟必须复现相同轨迹。


## 附录 A：项目一句话定义

**Property Simulation Sandbox 是一个以月度时间段为基础、从任意有效房产初始状态或历史快照出发、由可组合业务 Slice 驱动、生成带规则/输入来源记录的随机事件历史、经济 Ledger 和世界状态数据集的本地模拟工具。**


## 附录 B：最重要的边界

- Simulation 只由用户预先设置的运行边界/终止条件或用户月度停止命令结束；贷款结清等领域事件本身不会停止模拟。
- Initial State 是**起始事实**，不等于过去事件历史。
- Slice 是**计算规则的代码边界**，活动实例是用户配置的模拟对象；两者不要求一一对应。Slice 不是独立提交的账本。
- Event 是**事实**，Effect 是**变化**，Ledger 是**经济记录**。
- Monthly Snapshot 是**数据投影**，不是 Financial Report。
- GPUI 是**实验操作界面**，不是投资分析 Dashboard。
