# 领域模型

本文只保留当前计算和应用持久化必须遵守的领域规则。应用流程与未完成工作见[实施计划](implementation-roadmap.md)；依赖边界见[架构](architecture.md)。

## 时间、状态与单月计算

- `Month` 是一次模拟内从 0 开始的时间位置。`Month(0)` 是模拟初始化边界；第一段实际模拟期间是 `Month(1)`。期初 JournalEntry 记在 Month 0，首个完成的月度结果是 Month 1。继续计算时从最近完成月份加一得到下一期；尚无已完成月份时从 Month 1 开始。`Month(0)` 不是一个已完成模拟月，期间报表不得将它当作月度结果。区间端点均包含；产品不设更短的固定模拟时长，但当前 `Month(u16)` 表示最多 65,535 个计算月。停止月数、贷款期限和维修延迟都不能超过这个表示范围；月份运算使用 checked 算术。月份不表示真实日历年份；需要日历季节语义时应显式建模，不从月份序号隐式推断。
- 月度计算使用完整期初状态、当月冻结输入、有效活动状态和显式随机输入，生成可审计的月度结果；不读取隐式历史，也不依赖进程内跨月状态。
- 月度时序统一为月初冻结输入、事件归属当月、月末结算并形成快照；下一月从前一月结果显式取得延续状态。模块调用和单月组合接口仍按[架构方向](architecture.md)待定义。
- 期初状态包括所有会影响计算的已知用户事实和此前生成的延续状态。不得为了说明期初状态而伪造模拟开始前发生的交易。
- 用户可修正的结构错误应在计算前校验；缺失引用、币种/账户不符、超出模型支持范围、金额无法表示等均明确报错。checked 数值溢出是计算错误。经济上不寻常但可计算的结果不是错误。
- 负房产现金流允许继续计算。初始范围不模拟家庭偿付能力、资金不足处置、破产、贷款逾期/违约或止赎。
- 失败的单月调用不返回部分成功结果，也不修改调用方持有的期初 Ledger。由 Application 将 fatal 计算错误视为本次模拟失败。

## Slice、事件与结果

Slice 是一项内聚的领域计算能力，活动实例是用户配置或计算产生的模拟状态，两者不要求一一对应。各 Slice 的配置、专属规则、计算及输出应保持在清晰的 Slice 边界内；跨 Slice 的调用和组合接口尚待架构设计。一个月内，各项独立行为从一致的期初事实计算；除领域规则明确声明依赖外，不读取其他行为尚未结算的输出，也不依靠执行顺序形成依赖。明确生成未来月份有效的状态时，结果保留其来源和有效月份。

首版先实现当前确定的模拟项目，不要求算法达到最终精度。分布、采样及计算规则归属于定义其领域含义的 Slice，除非有明确的共享职责。随机输入及来源追溯须保持显式；不为尚无对应行为的未来计算提前建立通用框架。

必须区分：

- **Event**：发生的事实类型及其发生月份。金额由 Ledger 推导，不重复保存在 Event 中。
- **Decision**：用户或策略选择的响应。
- **JournalEntry**：一组在同一模拟月份记录的平衡复式分录。Month 0 用于初始化，Month 1 起用于模拟期间。

单次 Slice 结果保留该 Slice 的事件类型和本月 JournalEntry；Event 不重复携带金额，用户展示的金额从 Ledger 派生。原始随机样本只属于计算输入。当前计算产生的跨月输入可以从月份、已记录事件和 Ledger 推导，因此 Slice 不额外输出 Effect 状态变化。未来若新增无法由这些事实推导的跨月状态，应先为具体领域行为建模，再决定是否需要持久化。Application 汇集各 Slice 的月度结果并保存所需事实；Core 不需要再定义一个包裹所有 Slice 结果的 Snapshot。现金流从 Ledger 派生，按经营、投资、融资类别及调用方提供的小类分类，并保留期间、对应科目、分录位置和金额；现金流合计可从分类明细计算，不是第二套账务事实。

## 模拟 context、snapshot 与持久化

Core 不定义聚合全部设置与月度结果的 `Context` 或 `Snapshot`。Application 分别管理模拟名称、初始输入、固定的 Slice 配置、自动停止条件和随机 root，并按月份组织计算结果；Data Access 将这些独立事实持久化。各 Slice 的具体参数类型属于其计算契约，自动停止条件由独立的 StopCondition 能力定义。Application 在月度边界提供已完成 Month 和贷款结清状态进行停止判定；任一条件满足时，不启动下一月。用户结束运行由内存生命周期协调器处理，不属于停止条件。初始账务输入仅用于构造 Month 0 分录，不作为跨月设置更新的一部分；Loan 条款属于 Loan 配置。

用户关闭实例与领域规则将实例标记为已完成/终止是不同事实：前者可由用户重新启用，后者不因普通启用操作而复活。Application 根据已保存的用户配置、月度结果和 Ledger 状态组装后续月份的有效输入；非活跃实例不重复计算，但保留历史。普通生成实例从其有效月份参与计算。若模拟在实例有效前停止，该待处理实例仍可供审计，但尚无其未来月份的 Ledger 分录或现金流。

活动实例的生命周期由其领域行为决定，不因某月没有生成交易而自动结束：

- 租金和固定费用是持续活动。固定费用可代表房产税、地税、教育附加或公用事业等项目，不在 Core 中区分具体名目。固定费用每月按用户选择的单一方式计算：固定月金额，或房产总值乘以年费率并除以 12。模拟期间房产总值保持不变；金额按货币最小单位 half-up 舍入后过账。除用户关闭外，它们继续参与后续月份；当月金额舍入为零不代表活动结束。
- 维修由持续 `RepairOccurrence` 与一次性 `RepairCost` 实例建模。发生判断接收从模拟开始或最近一次已结算维修费用起算的完整月数，以及调用方提供的随机输入；单月发生率分子为 `25 + floor(125 × age / (age + 60))`，分母为 10,000。发生事件由 Application 用来创建费用实例。费用实例包含上限、正整数延迟、发生月份及本月结算输入；只在发生月加延迟后的月份生效，从零到上限可表示的整分范围内均匀抽样。Application 持久化待处理实例的发生月、应结算月和创建时采用的费用上限；在该月保存 `RepairCostSettled` 事件和账务结果时，原子地标记实例已结算。当前每月最多产生一个维修发生事件，因此发生月份可作为实例键。结算事件的月份就是最近结算月，金额为零时也记录事件但不生成零金额 JournalEntry；Application 可从该事件月份计算下一期的维修间隔输入，无需额外 Effect。
- 贷款是有终止条件的持续活动。当前首版每个模拟只支持一笔贷款。余额结清后，该贷款不再传入后续月份；用户关闭但尚未结清的贷款只是暂时不参与计算，不能被误记为已结清。
- 其他一次性活动若将来加入，应区分“一次性事件/交易”和“产生它的活动实例”。只有领域规则明确该实例已完成时才终止；同一交易不得在后续月份再次生成。

首版 Rental Slice 使用固定的每月租金金额。金额按币种最小单位 half-up 舍入后大于零时，输出 `RentCollected` 事件，并借记现金、贷记租金收入；舍入后为零时不产生收款事件或 Ledger 分录。现金账户和租金收入账户由 Application 提供，Slice 不创建或查找账户。

持久化保存重建模拟所需的用户配置、随机 root、活动实例定义及生命周期变化，以及每月实际输入和计算结果。初始化确认后，本次模拟的用户配置固定，不支持运行中修改配置、设置版本或未来生效月份。使用其他假设需要创建另一项模拟。不保存运行时 `SimulationSlice`、适配器或采样器对象。各项事实按各自职责组织，不要求把它们包装成 Core Context 或 Snapshot 实体；DTO 和数据库编码由 Data Access 定义。

Month 0 初始化 JournalEntry 和所有已提交的 Month 1+ JournalEntry 构成账务事实。期初余额由所有 Month 0 分录合并推导；初始化使用一笔或多笔平衡分录由 Application 决定，不影响余额含义。每月 Slice 返回的 JournalEntry 与持久化 Ledger 分录是同一事实。最新 Ledger 可由 Month 0 分录与全部已提交月度分录重建；期末余额直接从 Ledger 推导。现金流按 Month 1+ Ledger 分录及其对应科目推导，并按调用方提供的现金科目集合和科目分类映射归类；保留逐分录分类明细，不能只保存总和，不要求追踪到 Slice 活动实例。

月度推进用例不接收用户配置更新；配置在一次模拟内保持不变。Application 在月份边界检查初始化时配置的自动停止条件；已满足的条件阻止下一个月份开始。用户可在 Desktop 选择结束模拟并进入报告阶段，该操作不属于停止条件配置。每月实际输入及结果按 Month 持久化，成功保存后才推进下一月。计算或存储错误停止模拟并报告系统错误；不执行补偿或恢复。模拟结束后的长期结果保留策略不属于当前范围。配置生命周期见 [ADR-70](adr/ADR-70-immutable-simulation-configuration.md)。

## 随机性

- 概率分布定义可生成值及概率；采样器产生具体样本；随机源提供随机输入。Core 接受调用方提供的随机源/样本，不直接访问操作系统或分配并持有随机流。
- Application 在模拟初始化时从系统随机源生成一个随机 root，并作为模拟级状态独立持有和持久化。Random engine 从调用方传入的 root 和显式语义身份派生 Slice 所需的随机输入；领域计算不访问系统熵，也不分配或持有跨月随机流。派生方式不需要按月保存随机流游标。产品不承诺真随机性，也不承诺相同输入产生相同结果；模拟结束后的 root 保留策略不在当前范围内。这不构成失败运行恢复或结果重放承诺。
- 固定 seed 仅用于测试和诊断。初始随机范畴为环境、物理房产/组件、政策/宏观、居住/运营；范畴间按独立随机输入处理。相关性必须显式建模。

## Ledger 与金额

- 金额使用带显式币种的十进制定点数，有限表示范围为 `i128` 系数和最多 28 位 scale；禁止用二进制浮点表示入账金额。首版一个 Ledger 只使用一种货币，不兑换。
- 过账正金额按币种最小单位 half-up 舍入；中间计算保留十进制定点精度。超出表示范围或 checked 运算溢出时明确失败，不回绕或静默截断。
- 使用复式记账。每笔 JournalEntry 的借贷平衡；账户余额、资产负债表、损益和现金流均从 Ledger 中的 JournalEntry 推导，不维护竞争性的手工合计。
- 账户配置面向个人/家庭房产持有者，覆盖房产资产、现金、贷款、租金收入及运营费用。贷款本金偿还记为负债减少，不记为费用；现金流按经营、投资、融资分类。
- 期初资产、负债和权益是用户提供的起点事实，不代表模拟开始前发生的经济事件。Application 将其映射为一笔或多笔 Month 0 平衡 JournalEntry，作为初始化边界记录；Month 0 不是实际模拟期间，也不产生月度现金流。Opening equity 平衡资产与负债；允许负净值，只要求每笔期初分录平衡。
- 现金流分类明细保留 Ledger journal 中的分录位置、对应科目、期间、分类/小类及有符号金额。汇总只作为投影；分录位置用于定位，不要求额外的分录 ID 或 Slice 活动实例来源。

账户定义使用资产、负债、权益、收入和费用等类别及其借贷方向，并必须带有由 Application 提供的 `AccountRole`。`AccountRole` 是账户目录内稳定、唯一的语义角色，与 `AccountCode` 一一对应；目录可据此解析过账代码。`AccountClass` 只表示会计大类，不标识 JournalEntry 的分录账户。账户名称是展示文本。Application 在初始化时确定账户集合及现金流科目分类，并在 Ledger 验证或 Reporting 投影时注入目录和分类；Ledger 不拥有账户目录。Ledger 由币种和有序 JournalEntry 构成；Month 0 的 JournalEntry 记录初始化账务，Month 1 起的 JournalEntry 属于实际模拟期间。期初余额不是独立输入或长期账务事实，而是 Ledger 在 Month 0 边界的余额投影。Slice 返回 Month 1 或之后的月度 JournalEntry；Ledger 追加时校验账户引用、币种、月份顺序。期末余额从分录重算；若保留缓存，也只能是可核对的派生值。Reporting 和 audit 从账户目录、币种及 JournalEntry 序列推导结果，不维护竞争性的余额或现金流事实。现金流只纳入 Month 1 起的分录，Month 0 初始化分录不构成现金流。

## 固定利率等额摊还贷款

首版每个模拟只支持一笔固定名义年利率、全额摊还贷款，使用年利率除以 12 得到月利率。期限必须在 1 到 65,535 个月内，以确保贷款计划可由模拟的 Month 范围表示。以摊还起点本金 `B`、月利率 `j` 和剩余期数 `n` 计算月供：`P = B × j / (1 - (1 + j)^(-n))`；若 `j = 0`，则 `P = B / n`。月供按货币最小单位 half-up 舍入，条款不变时保持不变。

每月对月初余额计息，利息按货币最小单位 half-up 舍入；先付利息，再偿还本金。首次生效月即首个整月计息月和首个还款月，付款发生在月末。最后一期付款调整为剩余本金加当月利息，使贷款结清且不超额还本。贷款延续余额须与该笔贷款专属 Ledger 负债账户一致；利息费用账户可以共享。

Loan Slice 使用模拟开始时的贷款本金、年利率和总期限确定计划月供。每次月度评估接收当期月初贷款余额、由总期限和当前 Month 推导的剩余期限，以及现金、贷款负债和利息费用账户代码；Slice 不保存可变的跨月余额。只要 Ledger 中贷款余额仍大于零，就按期持续还款；余额结清后不再调用 Loan Slice。每笔还款输出 `LoanPayment` Event，并生成借记贷款负债/利息费用、贷记现金的平衡分录。本金、利息和期末余额从贷款的 Ledger 科目及分录推导，不另存剩余期限更新。

当前范围不支持多笔贷款、再抵押/房产套现或其他以房产融资产生的新贷款；这些活动属于家庭整体资产负债和经济活动记录，不属于当前房产模拟。未来若扩展到多笔房产贷款，需要一并重新设计贷款设置的实体标识、各贷款的账户映射和停止条件输入。当前也不模拟自定义还款、漏付、逾期、违约、浮动利率、再融资、提前还款、只付息或气球付款，也不模拟资产折旧/摊销。
