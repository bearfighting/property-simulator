# 领域模型与月度模拟语义

> 本文保留原规范章节编号，便于和既有讨论对应。首版实施基线以本文及 [实施路线](implementation-roadmap.md) 为准。

## 5. 时间模型与月度执行语义

### 5.1 月份

`YearMonth` 采用 YYYY-MM，是一次状态转移的当期标识；月份而非天是模型的基本精度。领域状态转移不持有总运行期限，也不决定是否继续。由更高层运行控制反复调用单期转移，并在其边界处理结束月份、用户停止或其他停止条件。无日级真实付款日、罚息或天气逐日轨迹的保证。

### 5.2 单期状态转移与充分状态

领域计算遵循“期初状态 + 当期冻结输入 + 当期随机输入 → 当期结果 + 期末状态”。给定相同的应用构建、完整期初状态、当期输入和随机输入，单期转移的计算语义固定；领域计算不读取运行总期限，也不依赖未显式传入的历史事件日志。

用户可纠正的结构错误只在输入验证边界产生：场景/规则配置、期初状态、月度输入冻结，以及运行前对模型支持范围、账户引用、现金分类和账务约束的验证。金额采用有限 `i128` 定点表示；超过其 scale/系数输入边界时拒绝，运算溢出则以明确的算术错误报告，不得回绕、截断或伪装成经济结果。金额范围远高于合理房产金额，故此边界不作为运行期限或偿付能力规则。验证成功后应得到不可变的 `Validated...` 输入；单期转移与财务投影不得再因缺少引用、分类或投影范围无效而失败。

验证 API 的错误类型表达调用方可修正的问题，并尽量汇总所有可发现问题。有限 `i128` 金额运算超界时，计算 API 返回明确的算术溢出错误；调用方将本次操作/期间标记为失败并保留此前已提交状态，不得把它伪装成输入错误或经济结果。其他内部不变量破坏、实现缺陷或基础设施故障由诊断/基础设施路径处理，也不能让模型把它们解释成经济活动或正常终止。

M2 单期 API 将验证后运行错误表示为 fatal 失败，包含 Slice 转移、账簿提交、期末推导或月度结果构造阶段、月份、可用的 trial/branch/activity 身份和原始类型错误。提案执行阶段尚未绑定运行身份时身份字段为空。输入、样本来源、资源声明、组合冲突和不支持 Effect 等可定位问题仍保留验证错误类型。fatal 要求上层停止本次调用，不表示正常终止，也不承诺恢复、回滚或持久化一致性。

期初状态必须包含继续计算所需的全部信息：已知事实、此前生成并仍有效的状态、未来计划/条款和账簿余额。随机输入在每个时间节点独立生成，不要求持久化未完成运行的随机发生器状态；从最近完成的月末快照继续属于新运行。若某条规则看似需要更早历史，先识别历史中真正影响当前计算的信息，并将其作为有定义的状态字段或派生摘要保存；不得让 Slice 隐式扫描完整历史来决定当期结果。事件与分录历史仍可为审计、展示和投影保存，但历史记录本身不是隐藏的计算输入。

此原则借鉴马尔可夫式的充分状态边界，不要求整个经济过程满足某个统计意义上的马尔可夫假设，也不要求现实变量相互独立。规则的条件依赖仍由状态、当期输入及明确的随机模型表达。

### 5.3 月度状态

每个 `MonthlyPeriod` 具有：month、opening snapshot reference、proposed/committed events、decisions、state effects、ledger transactions、closing snapshot reference、monthly totals、status。

### 5.4 规范化单期执行阶段

1. **Freeze Input**：调用方提供并冻结本期生效输入，校验结构、引用和规则前置条件。
2. **Build Context**：以完整期初状态、本期输入、当期标识和明确的随机输入建立只读计算上下文。
3. **Evolve/Propose**：各 Slice 实例从同一份期初状态、冻结输入及本实例显式样本独立计算，提出事件、状态 Effects 和经济流水；实例之间不读取或传递同月结果。
4. **Resolve**：按交换律、结合律及空结果单位元合并同月提案。组合边界拒绝不兼容状态写入和其他不满足组合契约的结果；不以执行顺序或跨实例读取来消解冲突。
5. **Commit/Close**：成功期次将 Effects、Ledger Transactions 和事件作为一个完整结果提交，计算当期派生视图并生成完整期末状态/快照。不可恢复的运行时错误会停止运行；错误发生后的回滚、恢复及持久化一致性不作保证。

单期转移到此结束，不负责选择下一期或判断运行是否结束。更高层运行控制在每次单期成功后决定是否再次调用；快速运行、逐期交互、用户月度停止命令和预设终止条件都复用同一单期转移，不进入 Slice 计算语义。

**组合约定：** 所有被接受的 Slice 实例结果组合都必须满足交换律和结合律，并具有空结果作为单位元；交换实例顺序、改变分组或并行计算不能改变结果。组合器只能合并兼容的结果；无法满足该约定的状态写入在提交前拒绝，不通过先后执行或读取其他实例结果来解决。

### 5.5 同月实例隔离

Slice 实例之间没有同月计算依赖。需要形成因果关系的规则必须在同一个 Slice 实例内部计算，或通过明确的期初状态/冻结输入表达；不得读取其他实例的当月输出，也不得用有限阶段、拓扑排序或执行顺序传递结果。

### 5.6 月度外部输入与结算

运行控制由单期计算之外的更高层调用方负责：它可设置结束月份、月末终止条件或逐期继续/停止。条件在当期转移成功并生成期末状态后评估；贷款结清、负现金流、出售等事实本身不会隐式终止运行，只有运行控制明确选择时才停止。用户逐期停止是调用控制，不是领域事件触发的交互式暂停。单期领域转移本身不要求提供某种终止机制。

每期转移之前，外部调用方可以调整未来参数/假设、提供本期已知状态，新增/调整/移除活动实例，并冻结本期输入。修改从指定生效月起生效，不改写已提交月份；若要修改已关闭月份，必须从其期末状态创建分支。用户设置期初资产和负债后，由账簿推导净资产/期初权益作为平衡项；若用户显式输入净资产，则校验资产 = 负债 + 净资产。设置可以涉及一个或多个资产或负债科目，开账事实不伪造成历史交易。若期间状态调整影响 Ledger 所表示的经济余额，须通过明确的 Effect 和平衡凭证反映，不能只覆盖账户余额。输入冻结前要确保活动组合及其允许的随机结果可计算、可表示并能被账务规则处理；通过该边界后，单期领域计算对允许输入必须给出结果。跟踪现金余额不足属于可观察的模拟结果，不触发运行失败、资金不足处置或偿付能力推断；账务效果按用户配置及普通活动规则表达，不额外推断特殊资金流向。任何有效输入下出现数值错误、账务拒绝或无法解决的活动冲突，均表示领域设计/实现缺陷，须通过修正规则和测试解决，不能作为领域结果返回。快速运行与逐期交互是调用方策略，二者调用同一单期领域转移。v1 不因未经配置的领域事件自动暂停，也不模拟破产/资金不足处置。保存用户输入设置及完成月份结果；系统生成的随机值、状态及来源无需作为额外恢复数据持久化。

首版语义：每期转移生成完整期末状态。用户可选择任一期末状态作为新分支起点，修改之后的参数/假设并重新运行；原分支保留，不能静默改写。重新运行从新的随机试验开始；相同设置既不保证复现先前轨迹，也不保证结果一定不同。用户保存已完成的月末快照/结果和最新设置；系统产生的 seed、随机发生器状态及未完成月份抽样不作为恢复数据。只拒绝结构缺失、数值无法表示、无法计算或违反账务完整性的输入；这些条件须在转移前发现。对已接受的输入，所有允许的随机结果和经济上不寻常但可计算的结果都必须形成输出，不得作为运行时领域错误。交互式领域决策暂停不属于首版要求。

### 5.7 运行控制与终止

运行仅在到达用户预先设置的运行边界/终止条件，或用户在月与月之间发出停止命令时结束。终止条件在月末快照生成后评估；用户停止时保留最后一个已完成月份。贷款结清、负现金流、出售或其他领域事件本身不会结束运行，除非用户明确将其设置为终止条件。模拟失败是失败诊断，不是正常结束条件。上述运行状态不属于领域状态转移输入或输出。


## 7. 业务 Slice 路线图与验收

### S1. Property Acquisition & Mortgage（首个房产领域 Slice）

**支持两种入口：**

- **New Acquisition**：购房发生于模拟内；通过用户配置和普通 Slice 效果生成购买、首付、交易费用、贷款及房产所有权状态变化。贷款不引入独立的资金用途/资金流向机制。
- **Existing Ownership**：模拟开始时已持有；直接载入房产资产和未偿贷款的 Opening State，**不伪造购房历史**。

**状态：** 房屋持有状态、贷款余额、固定年利率、剩余摊还月数、按余额/利率/期限推导的等额月供、计息规则及贷款状态。

**月度行为：** 按 ADR-14 从期初余额、剩余期限和固定年利率推导等额月供。生效月就是首个计息和还款月：月初生效，按整月计息，月末首次付款；之后每月计算利息、本金、现金流及继续计算所需状态，最后一期按剩余本息调整付款并结清。结清时可产生 `mortgage.paid_off` 事件；之后不再产生月供贡献，但 Simulation 继续。贷款余额是账面负债：每期用平衡 Ledger 分录反映本金减少、利息费用和现金付款，贷款状态余额须与 Ledger 负债余额对账。

**边界：** M3 将固定利率、等额摊还贷款作为普通 Slice 活动；相同条款的其他固定利率分期借款也可使用 ADR-14 规则。期初借款作为负债开账事实，不伪造模拟前的放款交易；之后本金、利息及现金按月入账。每笔贷款使用独立非 contra 负债科目，利息费用科目共享；每个实例延续余额必须与其负债科目一致，结清账户余额必须为零，详见 [ADR-23](adr/ADR-23-loan-ledger-account-granularity.md)。循环借款、只付息、浮动利率或到期气球付款等结构不属于 M3 贷款计算范围，须先另行明确计算规则，不能默认套用 ADR-14 公式。首版不模拟房产或其他资产的折旧/摊销；初始资产参考价值保持不变，除非未来加入明确的非现金估值规则。抵押顺位、HELOC、续约/浮动利率、提前还款和再融资均不作为 M3 要求。

**M3 关键测试：** 贷款计算的期初延续状态完整；每月付款分配、利息费用、本金减少、现金流贡献和 Ledger 余额一致；状态可连续推进且结清后运行仍可继续；现金流按 Slice 实例保留来源，并与其他实例的贡献顺序无关地求和。具体向量见 ADR-14 和测试向量文档。

### S2. Property Tax & Insurance

按年度、季度或月度规则产生应付/支付；模拟按月步进并归集结果。税费与保险分开分类；可配置金额、周期、涨幅与起始月份。**不将年度费用默认均摊为每月真实支付**，除非选择预算化/月缴规则。M4 首个确定性活动按 [ADR-24](adr/ADR-24-m4-operating-activity-contracts.md) 实现固定金额物业税日程：首个应付月份锚定月度、季度或年度周期，只在实际应付月生成费用和经营现金流；首版该规则不含涨幅/通胀，不补记运行起始月之前的付款。

测试：不同支付周期、年界、起始月份、金额调整、与 S1 同月现金合计。

### S3. Regular Maintenance & Exterior

除草、除雪、花园维护、定期检查。规则可为季节性、周期性或状态阈值；雪量等可由简化环境变量生成。记录事件与费用；无需日级天气仿真。

测试：季节、阈值、无雪不触发阈值除雪、自动策略、费用分类。

### S4. Component Deterioration & Repair

屋顶优先；再扩展热水器、供暖、管道。状态含年龄、状况、损伤、维修历史；自然演化与随机故障分开。事件可触发修补或更换；维修完成与付款可跨月。延期维修决策属于未来扩展，不属于 v1 交互式暂停流程。维修不等于等额增加资产市场价值。

测试：故障概率、维修后状态、延期后风险、事件因果、现金和状态一致性。

### S5. Occupancy & Rental

自住/出租/空置状态，租金计划、租客搬离、重新出租、空置成本。租客离开影响后续收租规则；是否当月全额收租必须有显式政策。

测试：空置无正常租金、租约起止、状态转换、跨 Slice 影响。

### S6. Utilities & Operating Costs

水电暖、服务费用；月度固定/季节/使用量相关模型。与气温、入住状态相关，但保持模块隔离。M4 首个随机活动按 [ADR-24](adr/ADR-24-m4-operating-activity-contracts.md) 消费本实例、本月份显式提供的整数用量样本，再乘冻结的固定单位资费并在入账边界舍入；Slice 不自行抽样，也不读取其他 Slice 的天气、入住或结果。首个模型不做用量单位转换、分数用量、季节资费或跨 Slice 状态传递。

测试：季节性、空置用量、异常费用和边界输入。

### S7. Valuation & Disposal（可选扩展）

估值变化属于资产状态而非现金收入。出售发生时，生成成交现金流、交易费用、清偿贷款、持有状态变化；出售后停止房产运营 Slice。模拟继续至用户配置的月末终止条件、结束月份或用户停止；出售本身不是隐式终止条件。

测试：出售清算不重复记账；已出售房产不再产生物业运营事件；未配置出售终止条件时模拟继续。

### 7.1 Slice 实施原则

先验证通用月度活动输入、计算、提交和投影路径，再实现具体领域规则。每个规则实现通过独立测试后，与已有实现组合验证；24/240 月只是可选回归场景。避免所有领域规则写完后才第一次整合。首个内存纵向切片包括：Scenario → 月度活动基础 → 确定性活动 → Ledger → 数据集；贷款规则随后作为首个房产领域 Slice 接入。CLI 属于核心领域和基础模拟流程完成后的应用阶段。


## 8. 事件、过程、决策与 Effects

### 8.1 事件边界

- **Process**：持续老化、计息、环境演化；不需要每月生成“老化发生”事件。
- **Event**：离散事实；如 `roof.leak_detected`、`mortgage.paid_off`。
- **Action/Decision**：用户或策略选择；如 `repair`、`replace`、`postpone`。
- **Effect**：状态修改、经济义务、现金交易、未来计划变化。

### 8.2 事件字段

```rust
struct SimulationEvent {
    id: EventId,
    period: YearMonth,
    kind: EventKind,
    source_slice: SliceId,
    subject: EntityId,
    cause_ids: Vec<EventId>,
    payload: EventPayload,
    trace: Option<EventTrace>,
}
```

建议稳定的 namespaced type ID：`mortgage.payment_completed`、`mortgage.paid_off`、`roof.leak_detected`、`maintenance.snow_removed`、`rental.tenant_departed`。事件类型与生成器一对多：同一个屋顶损坏事件可以由老化或暴风雪生成。

### 8.3 触发类型

`Scheduled`、`Periodic`、`Conditional`、`Stochastic`、`Decision`。触发机制不是互斥业务类别。

### 8.4 事件过滤原则

模拟直接影响现金、未来现金、物理/经济状态或其他重要事件条件的变化。普通晴天、植物开花等若不改变模型状态或风险，可作为环境输入而非正式事件。

### 8.5 决策策略

未来可支持 `Automatic`、`Interactive`、`ConditionalThreshold` 等决策策略，并记录请求、可选项、所选项、依据、关联事件和后续安排。交互式暂停及等待用户决策不属于 v1；v1 的决策由场景配置的自动规则处理。小额例行费用自动处理是未来策略示例，不是 v1 的通用规则。手动改变已结算历史须创建新分支，不直接改写旧记录。

### 8.6 Event Trace

事件追踪可选包含输入状态摘要、风险/阈值、随机抽样值、计算出的严重程度和成本参数，用于诊断或解释；运行/数据集元数据可记录一次应用版本，保存抽样轨迹不是恢复运行的要求。目标是规则可审计、结果可解释，而非展示伪精确的现实预测。


## 9. 随机性与概率模型

### 9.1 发生与后果分离

故障发生概率、损坏严重度、维修费用、维修持续月份应独立建模。风险不是事件；事件不等于成本。

### 9.2 首批工具

- Bernoulli：月度发生/不发生；
- Poisson：事件到达强度（适用时）；
- Weibull：年龄相关的失效时间/危险率；
- Categorical：严重程度；
- Lognormal 或有界分布：非负右偏费用；
- Scheduled/Threshold：确定性与条件事件。

进入有效配置的概率模型必须保证其所有允许抽样结果均能由领域金额和账务计算表示。理论上无上界的分布（例如未截断的 Lognormal）须配置明确的有限支持/上限，或采用其他可证明在请求区间内可表示的方式；不能让有效抽样在运行中造成数值溢出或账务计算错误，也不静默截断已抽出的值。

Weibull 失效分布：`F(t)=1-exp(-(t/eta)^beta)`，其中 t/eta 使用一致时间单位。月度条件概率为：

`p = 1 - exp(-[((t+Δ)/eta)^beta - (t/eta)^beta])`，Δ = 1/12 年（若 t 以年计）。

**不保证**在任何有限模拟区间内一定故障（例如 20 年）；更不把 Weibull 当作物理状况的唯一老化公式。

### 9.3 共享环境与相关性

天气、通胀、入住率等共享 Environment State 必须作为期初状态或冻结月度输入提供；需要按月生成时，在 Slice 实例计算前生成并冻结，不由一个 Slice 实例生成后再传给另一个实例。多个计算规则可读取同一份显式期初/冻结状态，规则间不互相调用。环境数据不必每次变化都写入 Event Log。首版多笔贷款实例彼此独立，不因共同贷款规则实现而建立贷款间相关性或联动。

### 9.4 随机流、回放与重模拟

随机输入按范畴/Slice/实体/用途隔离；程序启动时从操作系统取得 32 字节根熵，在内存中保存，并按 ADR-21 派生运行密钥及语义子流密钥。应用层可在运行/数据集级别记录应用版本；不为各模型单独记录标识，也不要求另行保存抽样轨迹或随机发生器状态。随机输入在不同时间节点独立生成；随机值允许偶然重复，不要求也不保证唯一。**历史回放**使用该分支保存的已完成 Effects/结果；从月末快照继续会创建新运行/试验，允许结果不同，但不保证必然不同。未完成月份和随机发生器状态不作为 checkpoint 恢复数据。固定 seed 可用于测试/诊断，不构成用户运行的重放承诺。随机协议详见 [ADR-21](adr/ADR-21-m3-run-randomness-and-persistence.md)。


## 10. Ledger：必要但克制

### 10.1 为什么要 Ledger

仅有月度 `income` / `expense` 无法正确表示购房、贷款发放、归还本金、利息、维修费用与估值变化。Ledger 是经济事实层，不等于 Financial Report。

### 10.2 建议最小账户

- `CashAccount`：现金余额；
- `LoanAccount`：未偿贷款本金；
- `PropertyAsset`：房产账面/参考估值状态（明确字段语义）；
- `ExpenseCategory`、`IncomeCategory`：分类与追溯。

领域可用 typed economic effects 表达业务变化，但所有已过账的 Ledger Transaction 在 v1 必须采用借贷复式记账并满足借贷平衡。领域 Effects 与 Ledger 分录可以分层表示，不能以轻量余额变化账本替代复式账簿。

### 10.3 交易与分录

```rust
struct LedgerTransaction {
    id: TransactionId,
    period: YearMonth,
    source_instance_id: ActivityInstanceId,
    source_slice: SliceId,
    output_key: String,
    source_event_id: Option<EventId>,
    entries: Vec<LedgerEntry>,
}

struct LedgerEntry {
    account_id: AccountId,
    side: DebitOrCredit,
    amount: Money,
    classification: EntryClassification,
}
```

每条分录的金额为非负金额，借方/贷方由独立方向字段表示；同一凭证借方合计必须等于贷方合计。账户余额方向由账户类型和科目定义，不能把带符号的业务余额变化当作复式记账分录。

Effect 和凭证可通过本 Slice 实例内的稳定事件键引用同一提案中的事件；协调器识别事件 ID 后将可选 `source_event_id` 写入输出来源。键找不到对应事件属于无效提案。Effect 还声明目标资源键，协调器据此识别共享状态写入；目标资源不同的同名 Effect 不构成冲突。过账后凭证仍保留来源实例、Slice、输出键和事件引用。

例如按贷款余额、期限和利率推导出的月供为 1,800，其中本金 1,250、利息 550：借记贷款负债 1,250、借记利息费用 550、贷记现金 1,800。`payment = principal + interest`，而不是把 1,800 全算作经营费用。若资金来自模拟范围外，必须按用户输入和账户范围规则表达对应分录，不得默认假设资金来源。

### 10.4 月度结算

每月保留：

- Opening balances；
- 完整交易明细；
- Operating cash inflows/outflows；
- Financing cash flows（贷款、注资等，分开分类）；
- Net cash change；
- Closing balances；
- Loan outstanding；
- World State snapshot。

公式：`closing_cash = opening_cash + sum(cash_changes)`。本项目采用月度模拟口径：模型生成的期间收入/费用，其权责发生和现金收付在同一个月度结算点处理，相关收入/费用与现金变动同月记录。这是模拟简化，不代表任何真实场景或会计/税务合规结论。首版不模拟应收应付与收付之间的时间差；未来若支持，需显式增加应收/应付状态及结算事件。现金流与非现金资产重估分开。年度费用按配置的规则入账；若模型表达年度实际支付，应在配置的月份记录，不自动均摊。

每月先进入用户输入边界。用户可以调整此前设定、从本月起生效的参数或假设，更新本月已知状态，也可以新增、调整或移除从本月生效的活动实例。输入冻结后，模型计算每项生效活动当月是否发生及其结果。月度现金流由各 Slice 实例提交并归因的带来源贡献组成；相关经济活动通过平衡 Ledger 分录过账，贡献是已提交现金影响的可追溯投影，不维护竞争的现金余额或替代总账。M3 贷款余额及本金/利息拆分必须与 Ledger 负债、费用和现金过账相符。概率模型若判定某活动本月发生并给出金额，由相应规则生成该活动的模拟结果，再参与当月汇总；概率模型本身不直接写现金余额或 Ledger。若用户输入改变本月由 Ledger 表示的经济余额，必须生成对应的 Effect 和平衡凭证；若要更改已关闭月份，则从该月快照创建新分支。

### 10.5 负现金流与家庭流动性

首版不模拟家庭整体现金、偿付能力、逾期、违约或止赎。房产相关月度净现金流允许为负；负值只表示在用户当前假设下，房产相关流出超过流入，不表示用户或家庭无力支付，也不会自动限制、暂停或终止模拟。用户可显式将负现金流或现金流阈值设为月末终止条件。CLI/GUI 可用颜色或提示文字标示负现金流，但提示属于展示层，不改变领域结果。

资金不足时的处置（例如外部注资、延迟支出或跳过维修）是可能的未来模型能力，不能作为 v1 的隐式行为。v1 不根据模拟现金余额推断用户是否实际付款，也不据此生成逾期、违约等事件。

若运行配置显式跟踪物业现金账户，该账户余额只代表模拟纳入的资金范围，不应默认解释为家庭全部可用现金。每项活动按自身经济性质提供平衡凭证，例如维修费用对应维修支出、购置对应资产变化；现金账户贷方余额表示负的模拟现金头寸，不推断范围外家庭资金、透支或其他融资。若用户要模拟外部注资或借款，必须显式输入对应活动和科目。首版不要求用户输入家庭全部资产和负债，只要求输入所选模拟范围内的期初账户和继续运行所需的状态。

贷款余额、剩余期限和利率是生成月供与贷款状态的模型输入；月供由 ADR-14 推导。首版不推演漏付、逾期利息、违约或止赎，也不支持低于应付利息的自定义还款计划。校验只拦截缺字段、非法数值或无法执行的计算；经济上不寻常但可计算的其他结果不要求用户修正。房产范围现金流为负同样只作为模拟结果输出。

### 10.6 模拟范围内的账务投影

核心可从复式 Ledger 派生所选房产模拟范围内的期初/期末资产与负债、期间收入与费用、以及现金流明细。这些是模拟数据集的投影，服务于多分支比较和外部分析；不宣称是法定/税务用途的正式财务报表，也不实现完整会计准则、IRR、NPV 或收益率 Dashboard。展示层可以选择如何呈现这些投影，外部程序可进一步分析。

### 11.1 World State

```rust
struct WorldState {
```

### 11.2 历史与快照

- 已完成月份的结果保留逐 Slice 实例的现金流贡献及来源；其他事件/效果按模型输出契约保存。
- 已完成月份的结果同时保留当期接受的月前更新及其来源/生效月。经济状态调整另存前后状态 Effect，并关联对应的平衡 Ledger 交易；其现金流贡献独立于 Slice 贡献归档。
- 月末快照保存从该状态继续所需的充分状态。
- 保存边界：保存已完成月份的月末快照/结果与最新用户设置。未完成月份、调度队列、系统生成的 seed 和 RNG 状态不要求持久化；从最近完成快照继续会创建新运行/试验。详见 [ADR-21](adr/ADR-21-m3-run-randomness-and-persistence.md)。
- M3 的快照和分支记录可用 `branch_id`、父快照引用和月份关系表达；不规定专用树形容器，也不要求同时装载所有分支。需要历史树视图时，可从这些引用构造。

运行存档与数据导出可以有不同用途；首版存档需保留已完成模拟历史和最新用户设置，不承诺恢复尚未完成的运行。

### 11.3 持久化

M3 先实现纯后端内存运行控制；每次调用通过参数接收用户配置更新及继续/停止意图，校验更新并决定是否推进下一期。存储接口和具体 SQLite 实现留待应用与持久化阶段。若采用持久化，完成月份的结果、状态快照和最新用户设置属于保存对象；未完成运行不作为恢复目标。

### 20.3 复式记账 domain

第一阶段采用标准借贷复式记账。余额符号统一为正数显示余额，借/贷方向由账户类型和科目定义；每张过账凭证借方合计等于贷方合计。期初状态通过期初余额/期初凭证进入账簿，并与 `InitialWorldState` 对账，不记作模拟期间收入或现金流。期初输入由用户提供所有已知资产与负债；收支参数作为未来期间生成假设，不能用来代替期初余额。

建议最小模型：

```rust
struct JournalEntry {
    account_id: AccountId,
    side: DebitOrCredit,
    amount: Money,
    classification: Option<EntryClassification>,
}

struct JournalTransaction {
    id: TransactionId,
    period: YearMonth,
    source: TransactionSource,
    entries: Vec<JournalEntry>,
    status: TransactionStatus,
}
```

本项目不是经营企业会计系统。首版以**个人/家庭持有的一套房产**为模拟主体，科目围绕房产相关资产、融资、收入与支出设计，不引入企业股本、应付工资、折旧税务申报等企业会计/税务流程。最小科目类型仍为资产、负债、权益、收入、费用；主要期初科目类别为纳入模拟范围的现金/银行等流动资产、房产参考资产、一项或多项抵押贷款及用户纳入范围的其他负债，以及用于开账平衡并与范围内净值核对的期初权益。模拟期间科目覆盖租金等收入，以及利息、物业税、保险、维护维修、水电等房产费用。若场景不含出租，租金收入科目余额为零即可。具体科目编码和细分在 Ledger 实现里确定；不得通过把贷款本金偿还记为费用来平衡现金变化。

首版先用个人/家庭主体和通用房产科目，不实现家庭持有与公司持有之间的税务、法律责任或报表差异。为未来扩展，凭证来源及可选维度应能标识持有主体/物业/用途，且科目定义不与某个 GUI 表单绑定；将来如公司持有需要不同科目表、权益结构或税务处理，再通过 `AccountingProfile`/科目表扩展，而不是把企业规则塞进个人科目。期初借贷差额通过明确的期初净值/权益来源平衡，并能与用户提供的资产负债和净值事实核对，不得用不透明的“杂项收入”抹平差额。

会计 ADR 和逐笔分录样例见 [ADR-13](adr/ADR-13-ledger-profile.md) 与 [测试向量](test-vectors.md)。资产负债表、利润表和直接法现金流展示口径及现金流分类由投影 API 明确；报表是从期初余额和已过账分录推导的视图，不是另行维护的第二套事实。首版负净资产允许继续模拟，只要求期初余额平衡。

**账务不变量**：每张已过账凭证借贷平衡；科目余额可由期初余额加已过账分录重算；纳入 Ledger 的现金余额与世界状态中的对应现金状态一致；贷款实例余额合计与对应 Ledger 负债余额一致；每项由 Ledger 表示的经济 Effect 可追溯到凭证；撤销或更正使用反向/调整凭证，不静默改写已过账历史。期间结账需要幂等保护，禁止重复提交。Slice 现金流贡献按 ADR-22 追踪已过账现金影响，不替代 Ledger。


### 20.4 利息与抵押贷款 domain

贷款规则处理固定利率等额摊还的抵押贷款及条款相同的分期借款，不要求每个实例单独定义 Slice 类型。M3 计算输入为期初余额、剩余摊还月数和固定年利率；活动时序提供生效月份，该月即首个计息/还款月，月供按 ADR-14 公式推导。贷款 Slice 逐实例生成现金流贡献及平衡 Ledger 交易，并保留继续计算所需状态；实例余额必须与该贷款独立负债科目余额一致，利息记入共享费用科目，见 [ADR-23](adr/ADR-23-loan-ledger-account-granularity.md)。首版不建模贷款间相关性或联动。规则为：名义年利率除以 12 得到月利率、对月初本金计整月利息、按余额/利率/剩余期限推导月供并在月末先付利息再还本金；中间计算保留十进制定点精度，月供和利息按币种最小单位 half-up 舍入，末期付款调整至结清。输入变更和非法边界见 [ADR-14](adr/ADR-14-mortgage-interest.md)；所有示例和 golden fixture 使用明确的舍入与利率约定。首版不模拟房产或其他资产的折旧/摊销。

首版按等额摊还公式推导月供。设当前摊还起点余额为 `B`，月利率 `j = r / 12`，剩余付款期数为 `n`，月供为 `P = B × j / (1 - (1 + j)^(-n))`；若 `j = 0`，则 `P = B / n`。月供在摊还起点按币种最小单位 half-up 舍入，并在条款未改变时保持不变。每月利息 `I_m` 按月初余额 `B_m × j` 计算并按最小货币单位 half-up 舍入；本金 `Q_m = P - I_m`，非末期余额 `B_(m+1) = B_m - Q_m`。最后一期实际付款调整为 `B_m + I_m`，从而结清且不超额还本。有效余额、期限和利率下，月供足以覆盖当期利息，不产生负摊还。数值向量见 [test-vectors.md](test-vectors.md#mortgage-vectors)。

月度顺序固定为：月初读取本金、剩余期限和当月生效条款 →（新贷款/条款变更时）计算并舍入等额月供 → 对月初余额计提整月利息 → 月末付款分配（生效月即首次付款月；利息优先、本金其次，末期结清）→ 生成利息费用、本金/负债变化、现金影响及平衡 Ledger 交易 → 更新余额和剩余期限 → 检查结清并发出事件。该规则不支持日级部分月份；条款变更首版须从月初生效。每笔贷款使用独立 Ledger 负债科目；结果追踪每个 Slice 实例对期间和累计现金流的影响。模拟期间新增贷款需要明确开账状态和融资现金流，不由一般条款更新隐式创建。

**算法边界：** M3 采用 ADR-14 的利息与付款规则，不预建通用策略框架。贷款规则通过 Slice 提案输出延续状态变化、逐实例现金流贡献及平衡 Ledger 交易；规则本身不直接修改共享状态或总账，不访问 UI/存储。运行/数据集元数据记录生成结果的应用版本一次，已完成结果保留输入快照；快照分支使用当前应用中的规则继续生成。应用升级不承诺旧算法自动迁移或持续可执行；规则变化随应用整体演进，并更新相关文档与测试向量。

贷款 Slice 为后续计算保留所需延续状态（如余额、固定利率、剩余期限和派生月供），逐实例输出当期现金流贡献、费用/负债变动及所需平衡 Ledger 交易；每笔贷款单独设置负债科目，利息费用科目共享，贷款本金和利息可从账簿投影中区分。用户提供期初余额、期限和利率，月供由 ADR-14 公式导出。首版使用固定利率等额摊还；贷款间相关性、续约、浮动利率、提前还款和不同司法辖区计息规则不纳入初始模型。

贷款数学测试不仅测试最终余额，也测试派生月供、逐月利息、本金拆分、余额演进及每一笔凭证。测试向量包括零利率、正常利率、极小余额、末期调整结清、月供舍入、无贷款状态及非法期限/利率/余额。


### 20.5 随机模型、试验流与分支

随机性属于核心 domain，第一阶段即纳入，不等到后续 Slice 完成后再补。随机模型按模拟范畴归属，首批范畴为：

- **自然环境**：天气/季节等外生环境变量；首版可以简化或配置驱动，不要求日级天气。
- **房屋与组件状态**：老化、磨损、故障风险、维修成本等物理过程。
- **国家/地区政策与宏观条件**：物业税规则、保险/监管参数、利率路径及通胀等；政策输入可为固定情景，也可在明确模型后随机生成。
- **居住与运营过程**：入住、租客搬离、空置及使用量等行为过程，可在对应 Slice 实施时纳入。

这些范畴是领域归属，实际概率模型可拆成多个 Slice。要区分三个概念：**概率分布**定义结果的概率法则和支持范围（如 Bernoulli、Weibull 条件故障概率、右偏维修费用）；**采样器**定义从分布产生具体值所用的算法；**随机流策略**定义采样器如何取得随机输入，以及如何隔离范畴、Slice 和实体。不同时间节点的随机输入按模型契约独立生成。Slice 只消费显式、类型化的样本，不调用采样器；样本携带实例、Slice、样本类别和期间来源，并在交给 Slice 前校验，月度结果再核对样本类别与活动实例；同一 Slice 可配合多个兼容采样器，兼容性在组合边界验证。

**首版相关性边界：** 自然环境、房屋/组件状态、政策/宏观条件、居住/运营过程这四类随机范畴各自组织概率模型和随机流；范畴间暂按独立处理，不实现共享潜变量、相关矩阵或因果相关抽样。该选择是首版简化假设，不声称现实世界变量互相独立，也不要求现在提供校准数据。Slice 可以读取期初状态或冻结输入中明确提供的环境/政策状态；这些值须在 Slice 计算前生成并冻结，不得通过另一个 Slice 的当月输出传递，也不得暗中引入跨范畴随机相关。只有具体模型表明相关性确有必要时，才增加相关机制并说明依据、输入和测试；不为假想需求预建相关性框架。分布、采样器与 Slice 的分离及样本契约先于随机流协议实现；随机流分配和代表性概率模型在 M3 实现。

- 保存随机试验 ID 及解释已完成结果所需的用户配置/来源；应用层在运行/数据集级别记录应用版本。系统生成的 seed 和 PRNG 状态不作为用户设置或恢复数据持久化；固定 seed 仅用于测试/诊断。
- 随机流按范畴/Slice/实体/用途隔离，避免无关 Slice 共享同一消费序列；不同时间节点产生的随机输入相互独立，随机值允许偶然重复。首版不同范畴的流相互独立；是否引入跨范畴相关性由具体模型需求决定。
- 随机协议按 ADR-21 固定：程序启动时从操作系统读取 32 字节根熵并仅保存在内存；每次运行使用 BLAKE3 keyed hashing 结合 `trial_id` 和进程内运行序号派生新的运行密钥；各语义子流使用 `ChaCha12Rng`，并由 BLAKE3 keyed hashing 从规范化身份元组派生 32 字节子流密钥。元组包含 trial、随机范畴、Slice、活动/实体、`YearMonth` 和样本用途/键；每个不同样本须有不同用途/键，同一采样器可从其子流连续取多个随机数。操作系统熵获取失败时模拟启动失败，不以系统时间替代。协议不构成重放承诺：不承诺相同设置或 seed 的精确重放，也不承诺相同设置必然产生不同结果。系统生成的密钥和发生器状态不作为用户设置或未完成运行恢复信息持久化。
- 已完成结果保留解释该结果所需的业务记录和用户设置；不为恢复未完成运行而保存额外系统生成状态。共享环境数据是否作为结果快照的一部分由对应模型的输出契约确定。
- 固定 seed 可用于确定性测试/诊断；产品的普通“从快照重新模拟”生成新试验，结果可以相同也可以不同。统计测试验证抽样符合数学定义的容许范围；统计正确性不等于现实校准有效性。
- Monte Carlo 扩展可对同一基础场景创建多个独立 trial ID/seed，每个 trial 按相同规则和参数运行，再由独立分析层汇总结果；首版只提供试验身份和随机流边界，不实现批量调度或统计报告。
- 规则一致性不变量：一次运行使用同一应用构建中的规则实现；每个月的有效用户参数快照明确记录。新 trial 的结果可以相同，也可以不同。


### 20.6 月度生命周期与 Slice 组合

核心协调器实现 Input → Open → Context → Evolve/Accrue → Propose → Resolve → Commit → Close。首版不暂停等待领域决策；外部输入在每月 Input 阶段更新并冻结。Slice 实例只读取同一期初状态、冻结输入和自己的显式样本；组合器按交换律、结合律合并可接受结果，拒绝不兼容写入，不提供实例依赖、拓扑阶段或同月因果展开。成功期次完整提交，运行时不可恢复错误不承诺回滚或持久化一致性。

Slice 契约至少声明 ID、所需输入、读取/写入资源、配置校验和提案函数，不声明其他实例依赖。输入边界校验实例自身配置；所有被接受的实例结果组合必须具有交换律、结合律和单位元，现金贡献、事件、Effects 与 Ledger 交易均遵守该组合约定。相同状态写入可幂等合并，不同写入值拒绝；账簿凭证保持独立并由 Ledger 批量投影。不能把资源冲突作为顺序处理或同月跨 Slice 传值的理由。

Slice 是计算规则的代码边界，活动实例是用户配置并在特定月份生效的模拟对象；两者不要求一一对应。活动实例由调用方赋予稳定 ID，协调器根据 trial/branch、月份、实例 ID、输出类型和稳定输出键派生结果 ID，不依赖执行顺序或并行分组。现金流贡献保留实例、Slice 和输出键来源，并可按期间和实例汇总；这项追踪不要求转成每实例 Ledger 账户。每次运行控制调用通过参数接收配置更新及继续/停止意图，先校验更新并冻结当期输入，再决定是否调用单期转移。概率分布定义概率法则，采样器产生具体样本，Slice 消费显式类型化样本；三者分别实现并在组合边界校验兼容性。具体首个随机模型属于实现选择，不是开始 M3 的前置设计问题。

首阶段组合顺序：

1. 先用确定性活动 + 复式 Ledger 验证通用活动结果、来源追溯和月度现金流投影。
2. 加入一个概率活动，验证模型抽样结果如何形成当月模拟记录并合入同月结果。
3. 再将贷款规则实现为普通领域 Slice，验证其逐实例现金流贡献和延续计算状态；按 [ADR-23](adr/ADR-23-loan-ledger-account-granularity.md)，每笔贷款使用独立负债科目并与各自延续余额对账，但不要求每项贷款定义独立的 Slice 类型。
4. 加入维修/安装等活动，验证不同规则实现的现金流在同月汇总，同时保留各自活动、Effect 和凭证。
5. 用上述组合验证保存已完成快照、从快照开始新运行、历史审计与回放。

租赁和未来可能需要的交互式决策能力按领域模型验证后加入；首版核心运行不暂停。界面不作为领域验证依赖。每个计算规则实现使用短期确定性案例、边界测试和组合不变量；24/240 月是可配置的回归样例，按风险选择，不要求每个小改动都跑固定 240 月。
