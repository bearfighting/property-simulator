# 领域模型

本文只保留当前计算和应用持久化必须遵守的领域规则。应用流程与未完成工作见[实施计划](implementation-roadmap.md)；依赖边界见[架构](architecture.md)。

## 时间、状态与单月计算

- `Month` 是一次模拟内从 0 开始的月份序号；每次模拟都从 `Month(0)` 开始，开账 Ledger 表示该月开始前的事实。继续计算时从最近完成 Snapshot 的 Month 推导下一期，不重设起始月份。它标识计算期间，也可作为该模拟内月度结果的唯一键。区间端点均包含；模拟没有固定时长；月份运算使用 checked 算术。月份不表示真实日历年份；需要日历季节语义时应显式建模，不从月份序号隐式推断。
- 月度计算使用完整期初状态、当月冻结输入、有效活动状态和显式随机输入，生成可审计的月度结果；不读取隐式历史，也不依赖进程内跨月状态。
- 月度时序统一为月初冻结输入、事件归属当月、月末结算并形成快照；下一月从前一月结果显式取得延续状态。模块调用和单月组合接口仍按[架构方向](architecture.md)待定义。
- 期初状态包括所有会影响计算的已知用户事实和此前生成的延续状态。不得为了说明期初状态而伪造模拟开始前发生的交易。
- 用户可修正的结构错误应在计算前校验；缺失引用、币种/账户不符、超出模型支持范围、金额无法表示等均明确报错。checked 数值溢出是计算错误。经济上不寻常但可计算的结果不是错误。
- 负房产现金流允许继续计算。初始范围不模拟家庭偿付能力、资金不足处置、破产、贷款逾期/违约或止赎。
- 失败的单月调用不返回部分成功结果，也不修改调用方持有的期初 Ledger。由 Application 将 fatal 计算错误视为本次模拟失败。

## Slice、事件与结果

Slice 是一项内聚的领域计算能力，活动实例是用户配置或计算产生的模拟状态，两者不要求一一对应。各 Slice 的配置、专属规则、计算及输出应保持在清晰的 Slice 边界内；跨 Slice 的调用和组合接口尚待架构设计。一个月内，各项独立行为从一致的期初事实计算；除领域规则明确声明依赖外，不读取其他行为尚未结算的输出，也不依靠执行顺序形成依赖。明确生成未来月份有效的状态时，结果保留其来源和有效月份。

首版先实现当前确定的模拟项目，不要求算法达到最终精度。分布、采样及计算规则归属于定义其领域含义的 Slice，除非有明确的共享职责。随机输入及来源追溯须保持显式；不为尚无对应行为的未来计算提前建立通用框架。

必须区分：

- **Event**：发生的事实。
- **Decision**：用户或策略选择的响应。
- **Effect**：经过验证的状态变化。
- **Ledger transaction**：该经济行为的复式账务记录。

月度结果保留事件、状态变化、本月 Ledger 凭证增量、样本/来源关系、Ledger 派生的逐交易及逐活动实例现金流明细、期末状态和继续计算所需的贷款延续值。现金流合计可从明细计算；它不是第二套账务事实。

## 模拟 context、snapshot 与持久化

Context 是继续模拟所需的类型化状态，包含必需的模拟名称、用户初始设置、可选的最新设置和由 Application 取得的模拟级随机 root。模拟名称是独立元数据，不参与计算；若用户未提供，Application 在创建 Context 前生成名称，Core 不读取系统时间。`UserSettings` 包含初始值、`Vec<StopCondition>` 和按 `SliceKind` 组织的 Slice 设置。初始值包括币种、房产价值、期初贷款余额及固定贷款条款；期初权益由房产价值减贷款余额推导，期初现金默认为零。初始值在模拟开始后不可更改；更新生成新的 Context，保留初始值、模拟名称和 root。最新设置为空时初始设置生效；有用户更新时最新设置生效。任一停止条件满足即停止；月度边界在开始下一月前依据最近完成 Snapshot 检查，停止命令仍是独立命令。每月实际生效的设置随 Snapshot 保存。Context 不保存起始 Month，也不保留单独的命令历史。Snapshot 是已完成月份的类型化结果，保留当月实际输入、事件、Effect、Ledger 增量、期末状态和活动生命周期变化。Core 定义这些值的领域语义；Application 决定用例流程及跨月如何应用变更，Data Access 负责持久化映射。各 Slice 的具体参数字段仍待确定。

用户关闭实例与领域规则将实例标记为已完成/终止是不同事实：前者可由用户重新启用，后者不因普通启用操作而复活。跨月流程依据 Context 和此前 Snapshot 得出后续月份的有效状态；非活跃实例不重复计算，但保留历史。普通生成实例从其有效月份参与计算。若模拟在实例有效前停止，该待处理实例仍可供审计，但尚无其未来月份的 Ledger 交易或现金流。

活动实例的生命周期由其领域行为决定，不因某月没有生成交易而自动结束：

- 租金、房产税和公用事业是持续活动。除用户关闭或以后加入明确的领域终止条件外，它们继续参与后续月份；当月金额为零、未到缴费月份或没有现金流，不代表活动结束。
- 维修由持续 `RepairOccurrence` 与一次性 `RepairCost` 实例建模。发生判断使用显式 `RepairHistory`，发生事件生成费用实例，按费用实例的正整数延迟在未来月份结算。两个 Slice 的行为、输入、计算和输出在各自职责边界内定义；跨月流程负责续传待处理实例。
- 贷款是有终止条件的持续活动。余额结清后，该贷款实例成为已完成状态，不再传入后续月份；用户关闭但尚未结清的贷款只是暂时不参与计算，不能被误记为已结清。
- 其他一次性活动若将来加入，应区分“一次性事件/交易”和“产生它的活动实例”。只有领域规则明确该实例已完成时才终止；同一交易不得在后续月份再次生成。

持久化只需保存可重建活动实例的类型化定义、标识、用户启用选择和模型生命周期变化，不保存运行时 `SimulationSlice`、适配器或采样器对象。Context 在创建时及接受用户更改时持久化；没有用户更改时，不要求每月重复写入整份 context。每月实际生效输入与计算输出仍随该月结果保存。Context 与 snapshot 的物理组织及字段编码尚待数据访问设计。

Ledger 开账事实和所有已提交交易构成经济事实。每月结果中的 Ledger 更新与持久化 Ledger 交易是相同事实。最新 Ledger 可由开账事实与全部已提交交易取得；期末余额投影可以随 snapshot 保存，但须能从 Ledger 核对。现金流按 Ledger 交易、现金分录和来源推导，保存逐活动实例/Slice 的变化明细，不能只保存总和。

月度推进用例可接收用户 context 更改或停止命令；Application 先应用并单独持久化已接受的 context 更改，再停止或继续计算。每月实际生效输入及完整结果保存在唯一的月度快照 DTO 中，成功保存后才推进下一月。计算或存储错误停止模拟并报告系统错误；不执行补偿或恢复。模拟结束后的长期结果保留策略不属于当前范围。

## 随机性

- 概率分布定义可生成值及概率；采样器产生具体样本；随机源提供随机输入。Core 接受调用方提供的随机源/样本，不直接访问操作系统或分配并持有随机流。
- Application 在创建模拟 Context 时从系统随机源生成随机 root，并将 root 与初始用户设置一并保存于 Context，供该模拟持续使用直到结束。Random engine 从 root 和显式语义身份派生 Slice 所需的随机输入；领域计算不访问系统熵，也不分配或持有跨月随机流。若使用这种派生方式，Snapshot 不需重复保存随机流状态。产品不承诺真随机性，也不承诺相同输入产生相同结果；模拟结束后的 root 保留策略不在当前范围内。这不构成失败运行恢复或结果重放承诺。
- 固定 seed 仅用于测试和诊断。初始随机范畴为环境、物理房产/组件、政策/宏观、居住/运营；范畴间按独立随机输入处理。相关性必须显式建模。

## Ledger 与金额

- 金额使用带显式币种的十进制定点数，有限表示范围为 `i128` 系数和最多 28 位 scale；禁止用二进制浮点表示入账金额。首版一个 Ledger 只使用一种货币，不兑换。
- 过账正金额按币种最小单位 half-up 舍入；中间计算保留十进制定点精度。超出表示范围或 checked 运算溢出时明确失败，不回绕或静默截断。
- 使用复式记账。每笔已过账交易的借贷平衡；账户余额、资产负债表、损益和现金流均从期初余额及已过账分录推导，不维护竞争性的手工合计。
- 账户配置面向个人/家庭房产持有者，覆盖房产资产、现金、贷款、租金收入及运营费用。贷款本金偿还记为负债减少，不记为费用；现金流按经营、投资、融资分类。
- 期初资产、负债和权益是起点事实，不生成模拟期间凭证或现金流。Opening equity 平衡资产与负债；允许负净值，只要求期初账簿平衡。
- 现金流明细保留 Ledger journal 中的交易位置、来源活动/Slice、期间、分类及有符号金额。逐来源结果可核对到各自 Ledger 现金分录；汇总只作为投影。交易位置用于定位，不要求额外的交易 ID。

账户定义使用资产、负债、权益、收入和费用等类别及其借贷方向，并可带有由 Application 提供的可选机器可读 `AccountRole`。role 是不透明键，不从账户名称或代码推断；reporting 明确映射自己支持的 role。Application 在模拟初始化时确定本次账户集合、Ledger 币种和开账事实并提供给 Ledger；Ledger 不创建账户或月份。每个账户至多有一项正数期初余额，零余额省略；期初借方与贷方总额必须相等，资产、负债与权益的平衡由此体现。期初余额是起点事实，不伪装成历史凭证。Slice 直接返回零个或多个 `JournalEntry`；entry 构造校验分录金额和借贷平衡，Ledger 接收时再校验账户引用、币种、月份顺序及余额算术。Ledger 只追加，失败的追加不改变账簿；账户净余额从开账事实与 journal 推导，借方余额为正、贷方余额为负。报告与 audit 从开账事实和已追加 journal entry 推导，不维护竞争性的余额或现金流事实。

## 固定利率等额摊还贷款

首版对固定名义年利率、全额摊还贷款使用年利率除以 12 得到月利率。以摊还起点本金 `B`、月利率 `j` 和剩余期数 `n` 计算月供：`P = B × j / (1 - (1 + j)^(-n))`；若 `j = 0`，则 `P = B / n`。月供按货币最小单位 half-up 舍入，条款不变时保持不变。

每月对月初余额计息，利息按货币最小单位 half-up 舍入；先付利息，再偿还本金。首次生效月即首个整月计息月和首个还款月，付款发生在月末。最后一期付款调整为剩余本金加当月利息，使贷款结清且不超额还本。贷款延续余额须与该笔贷款专属 Ledger 负债账户一致；利息费用账户可以共享。

首版不模拟自定义还款、漏付、逾期、违约、浮动利率、再融资、提前还款、只付息或气球付款，也不模拟资产折旧/摊销。新增贷款及相应融资现金流必须由明确输入表达，不能由普通条款更改隐式产生。
